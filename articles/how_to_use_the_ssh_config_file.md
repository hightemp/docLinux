# Как использовать файл конфигурации SSH

Источник: [How to Use The SSH Config File](https://phoenixnap.com/kb/ssh-config)

Милица Данцук (phoenixNAP) · 12 декабря 2025 · рубрики Networking, ssh

Протокол SSH создаёт защищённое соединение между двумя удалёнными машинами. Файл конфигурации SSH помогает легко настраивать значения по умолчанию для этих соединений и упрощает SSH-подключения.

**Эта статья объясняет, как использовать файлы конфигурации SSH для управления SSH-соединениями.**

![How to Use The SSH Config File](/images/415cc48f81f609d134488e6a9e9e1c97.png)

Предварительные требования

* Доступ к терминалу.
* Доступ к текстовому редактору, например [nano](https://phoenixnap.com/kb/use-nano-text-editor-commands-linux) или [Vim](https://phoenixnap.com/kb/vim-commands-cheat-sheet).
* [Удалённый сервер](https://phoenixnap.com/kb/ssh-to-connect-to-remote-server-linux-or-windows) для проверки соединений.

## Что такое файлы конфигурации SSH?

Файлы конфигурации SSH — мощный инструмент для автоматизации SSH-соединений. Расположение пользовательского файла конфигурации по умолчанию — _~/.ssh/config_, тогда как общесистемный файл конфигурации для всех пользователей — _/etc/ssh/ssh_config_. Оба расположения должны оставаться неизменными.

![SSH config file local and global locations cmd output](/images/5fe7e0f56d546d176d2de8346b1348af.png)

Файл конфигурации — это обычный текстовый файл с различными опциями SSH-соединений. Используйте любой [текстовый редактор](https://phoenixnap.com/kb/best-linux-text-editors-for-coding), чтобы открыть, прочитать или отредактировать файл конфигурации.

## Как используются файлы конфигурации SSH?

Когда файл конфигурации SSH находится в нужном месте, запустите команду **`ssh`** с корректными параметрами, чтобы прочитать опции, заданные в файле конфигурации.

Например, если файл конфигурации SSH содержит пример секции **`Host`** вида:

```text
Host my-website.com
    HostName my-website.com
    User my-user
    IdentityFile ~/.ssh/id_rsa
```

Эта команда **`ssh`** подключится к удалённому хосту:

```bash
ssh my-website.com
```

Команда применяет опции для заданного **`HostName`** сервера, такие как **`User`** и **`IdentityFile`**. Файл конфигурации содержит информацию о соединении по умолчанию для хоста, избавляя от необходимости вводить детали соединения вручную.

Цепочка из нескольких опций хостов и подстановочных знаков позволяет задавать значения по умолчанию для всех серверов или добавлять специфичные параметры для некоторых серверов.

## Как создать файлы конфигурации SSH?

Чтобы создать файл конфигурации SSH, сделайте следующее:

1\. Откройте терминал (**CTRL**+**Alt**+**T**).

2\. Перейдите в каталог _.ssh_:

```bash
cd ~/.ssh
```

**Примечание:** если каталог не существует, создайте его командой mkdir: **`mkdir ~/.ssh`**.

3\. С помощью текстового редактора создайте и откройте файл config. Например, если вы используете nano, выполните:

```bash
nano config
```

Редактор создаст файл и откроет его для редактирования.

4\. Заполнив файл информацией, закройте nano и сохраните изменения.

5\. Дайте права на чтение и запись только текущему пользователю:

```bash
chmod 600 ~/.ssh/config
```

Файл требует строгих прав из-за потенциала для злоупотреблений.

Разделы ниже объясняют, как форматировать файл конфигурации SSH, и все доступные параметры.

### Формат файла конфигурации SSH

Файлы конфигурации SSH следуют определённому формату для корректной работы. Пример файла конфигурации выглядит так:

```text
Host hostname_1
    PARAMETER argument
    PARAMETER argument

Host hostname_2
    PARAMETER argument

Host *
    PARAMETER argument
```

![SSH config sample file structure](/images/8aaa3c17bacabe78593e95fc9b83fc3e.png)

Файл конфигурации SSH разделён на **секции Host, каждая — с конкретными опциями конфигурации для заданного** хоста. Аргументом может быть точное имя хоста, IP-адрес или шаблон соответствия.

Используйте пробел как разделитель между параметрами и аргументами или знак равенства (**`=`**). Если значение содержит пробелы, заключите строку в кавычки (**`"`**). Для нескольких аргументов используйте список через запятую.

Следующие символы помогают определять разные шаблоны:

* Звёздочка (**`*`**) соответствует нулю или более символам. Например, **`Host *.com`** соответствует любому хосту, заканчивающемуся на домен _.com_, тогда как **`Host *`** соответствует любому хосту.
* Знак вопроса (**`?`**) соответствует ровно одному символу. Например, **`192.168.1.?`** соответствует всем хостам в диапазоне **`192.168.1.[0-9]`**.
* Восклицательный знак (**`!`**) инвертирует шаблон. Например, **`!192.168.1.1, 192.168.1.*`**

Пустые строки и строки, начинающиеся со знака решётки (**`#`**), — комментарии. SSH игнорирует эти строки и использует первые найденные значения при поиске по файлу конфигурации. Помещайте специфичную для хостов информацию ближе к началу файла, а общую информацию по умолчанию — ближе к концу.

### Параметры файлов конфигурации SSH

Файл конфигурации SSH предоставляет множество параметров для настройки SSH-соединений. Ниже — краткое описание всех доступных ключевых слов параметров и их функциональности.

**Примечание:** параметры и аргументы чувствительны к регистру.

#### AddressFamily

Параметр **`AddressFamily`** задаёт семейство адресов для использования при подключении по SSH. Возможные аргументы: **`inet`** (только IPv4), **`inet6`** (только IPv6) или **`any`**.

#### BatchMode

Параметр **`BatchMode`** контролирует, запрашивать ли пароль. Значение по умолчанию — **`no`**, и пароль запрашивается.

Установите аргумент **`yes`**, если используете SSH в скриптах.

#### BindAddress

Параметр **`BindAddress`** помогает указать адрес привязки в системе с несколькими адресами. Если значение **`UserPrivilegedPort`** — **`yes`**, опция не работает.

#### ChallengeResponseAuthentication

Параметр **`ChallengeResponseAuthentication`** контролирует, использовать ли challenge-response [аутентификацию](https://phoenixnap.com/glossary/what-is-authentication) при подключении к серверу по SSH. Значение по умолчанию — **`yes`**.

#### CheckHostIP

Параметр **CheckHostIP** говорит SSH, выполнять ли дополнительные проверки IP-адреса хоста в файле _known_hosts_. Параметр позволяет SSH обнаруживать изменения ключей хоста. По умолчанию значение — **`yes`**.

#### Cipher

**`Cipher`** — параметр протокола версии 1, задающий тип [шифра](https://phoenixnap.com/glossary/what-is-a-cipher) для [шифрования](https://phoenixnap.com/glossary/encryption-definition) сессий. Поддерживаемые типы: **`blowfish`**, **`des`** и **`3des`** (по умолчанию).

#### Ciphers

Параметр **`Ciphers`** задаёт тип шифра для шифрования сессий в протоколе версии 2. Доступные шифры и значения по умолчанию:

```text
aes128-ctr, aes192-ctr, aes256-ctr, arcfour256, arcfour128,
aes128-cbc, 3des-cbc, blowfish-cbc, cast128-cbc, aes192-cbc, aes256-cbc, arcfour
```

Указывайте несколько шифров списком через запятую.

#### ClearAllForwardings

Параметр контролирует, очищать ли всё динамическое, локальное и удалённое [перенаправление портов](https://phoenixnap.com/kb/ssh-port-forwarding) из командной строки или файла конфигурации. Значение по умолчанию для **`ClearAllForwardings`** — **`no`**.

Запуская SSH из командной строки, очищайте любую предустановленную конфигурацию с помощью этого параметра.

#### Compression

Параметр **`Compression`** контролирует, использовать ли сжатие. Значение по умолчанию — **`no`**.

#### CompressionLevel

Параметр **`CompressionLevel`** задаёт степень сжатия, если параметр **`Compression`** — **`yes`**. Уровень — целое число между **`1`** (быстрейшее, худшее) и **`9`** (медленнейшее, лучшее), уровень **`6`** — по умолчанию. Параметр применяется только к протоколу версии 1.

#### ConnectionAttempts

Параметр **`ConnectionAttempts`** контролирует, сколько попыток соединения делать перед выходом. Одна попытка происходит в секунду, количество попыток по умолчанию — **`1`**. Добавьте параметр в скрипт, если попытки иногда проваливаются.

#### ConnectTimeout

Параметр **`ConnectTimeout`** определяет таймаут соединения в секундах при подключении к SSH-серверу. Таймаут по умолчанию — системный TCP-таймаут.

#### ControlMaster

Параметр **`ControlMaster`** позволяет разделять соединение через одну сеть. Параметр допускает следующие аргументы:

* **`yes`** — включает прослушивание управляющего сокета, заданного в **`ControlPath`**.
* **`no`** — отключает прослушивание, но по-прежнему позволяет подключаться к **`ControlPath`** через сетевое соединение мастера (по умолчанию).
* **`ask`** — слушает соединения и требует подтверждения. Если **`ControlPath`** не открывается, SSH продолжает без подключения к мастер-соединению.
* **`auto`** — допускает оппортунистическое мультиплексирование и создаёт новое соединение, если его не существует.
* **`autoask`** — объединяет опции **`ask`** и **`auto`**.

#### ControlPath

Параметр **`ControlPath`** содержит информацию для управляющего сокета в разделяемых соединениях. Аргумент **`none`** отключает разделение соединения. Если указывается путь, доступны следующие подстановки:

* **`%l`** — локальное имя хоста.
* **`%h`** — целевое имя хоста.
* **`%p`** — порт соединения.
* **`%r`** — имя пользователя удалённого входа.

Минимальная рекомендация — **`%h`**, **`%p`** и **`%r`**, чтобы у соединений были уникальные идентификаторы.

#### DynamicForward

Параметр **`DynamicForward`** включает динамическое перенаправление TCP-порта через защищённый канал. Формат — **`bind_address:port`** или **`bind_address/port`**.

Используйте **`localhost`** как адрес привязки, чтобы привязать порт для локального использования, или **`*`**, чтобы сделать порт доступным со всех интерфейсов.

#### EnableSSHKeysign

Параметр **`EnableSSHKeysign`** из глобального файла конфигурации SSH (_/etc/ssh/ssh_config_) запускает программу, генерирующую цифровые подписи для аутентификации на основе хоста. Доступные аргументы: **`yes`** или **`no`**.

#### EscapeChar

Параметр **`EscapeChar`** определяет escape-символ. Escape-символ по умолчанию — тильда (**`~`**). Используйте **`none`**, чтобы отключить escape-символы.

#### ExitOnForwardFailure

Параметр **`ExitOnForwardFailure`** указывает, разрывать ли соединение при неудаче перенаправления портов. Возможные аргументы: **`yes`** или **`no`** (по умолчанию).

#### ForwardAgent

Параметр **`ForwardAgent`** контролирует, пересылать ли агент аутентификации на удалённую машину. Значение по умолчанию — **`no`**. Включайте опцию с осторожностью: пользователи, способные обойти права на файлы, могут получить доступ к локальному агенту.

#### ForwardX11

Параметр **`ForwardX11`** управляет перенаправлением X11 (оконной системы) на удалённую машину. Значение по умолчанию — **`no`**, что запрещает перенаправление управления X11.

Пользователи, обходящие права на файлы и включившие **`ForwardX11Trusted`**, могут осуществлять мониторинг нажатий клавиш и другие потенциально нежелательные действия, когда значение параметра — **`yes`**.

#### ForwardX11Trusted

Параметр **`ForwardX11Trusted`** включает полный контроль над X11-клиентами к исходному дисплею. Значение по умолчанию — **`no`**, и токен xauth для X11-клиентов истекает через двадцать минут. Включайте опцию с осторожностью, так как она снимает все ограничения.

#### GatewayPorts

Параметр **`GatewayPorts`** определяет, могут ли удалённые хосты подключаться к локально перенаправляемым портам. Значение по умолчанию — **`no`**, и локально перенаправляемые порты привязываются к адресу loopback, когда отключено.

#### GlobalKnownHostsFile

Параметр **`GlobalKnownHostsFile`** позволяет указать другое расположение глобального файла ключей хостов. Расположение по умолчанию — _/etc/ssh/ssh_known_hosts_.

#### GSSAPIAuthentication

Параметр **`GSSAPIAuthentication`** — опция протокола версии 2, контролирующая, включён ли GSSAPI. GSSAPI предоставляет доступ к различным [службам безопасности](https://phoenixnap.com/kb/linux-ssh-security); по умолчанию параметр отключён и установлен в **`no`**.

#### GSSAPIKeyExchange

Параметр **`GSSAPIKeyExchange`** — опция протокола версии 2, включающая обмен ключами на основе GSSAPI; по умолчанию **`no`**. Серверу не нужен ключ хоста, когда значение параметра — **`yes`**.

#### GSSAPIClientIdentity

Параметр **`GSSAPIClientIdentity`** указывает идентичность клиента, которую SSH использует для GSSAPI. По умолчанию у параметра нет идентичности клиента, и SSH использует идентичность по умолчанию.

#### GSSAPIDelegateCredentials

Параметр **`GSSAPIDelegateCredentials`** контролирует, пересылать ли учётные данные на сервер. Значение по умолчанию — **`no`**, и учётные данные не делегируются серверу. Параметр работает только для протокола версии 2.

#### GSSAPIRenewalForcesRekey

Параметр **`GSSAPIRenewalForcesRekey`** вызывает смену ключей (rekeying) SSH-соединения при обновлении учётных данных GSSAPI. По умолчанию параметр — **`no`**.

#### GSSAPITrustDns

Параметр **`GSSAPITrustDns`** контролирует, доверять ли DNS для нормализации имени хоста. Значение аргумента по умолчанию — **`no`**, и имя хоста, переданное в командной строке, передаётся в GSSAPI как есть. Параметр доступен для протокола версии 2.

#### HashKnownHosts

Параметр **`HashKnownHosts`** контролирует, хешировать ли известные записи хостов в файле _~/.ssh/known_hosts_. SSH использует хешированные значения как обычно, не раскрывая содержимое файла.

По умолчанию параметр установлен в **`no`**. Измените значение на **`yes`**, чтобы хешировать все будущие записи. Старые записи останутся без изменений.

#### HostbasedAuthentication

Параметр **`HostbasedAuthentication`** указывает, пробовать ли аутентификацию на основе [rhost](https://phoenixnap.com/glossary/rhosts) с [аутентификацией по публичному ключу](https://phoenixnap.com/kb/ssh-with-key). Значение параметра по умолчанию — **`no`** и применяется только к протоколу версии 2.

#### HostKeyAlgorithms

Параметр **`HostKeyAlgorithms`** задаёт порядок предпочтения алгоритмов ключей хоста в протоколе версии 2. Порядок по умолчанию — **`ssh-rsa,ssh-dss`**.

#### HostKeyAlias

Параметр **`HostKeyAlias`** позволяет задать псевдоним для ключа хоста, используемый при сохранении или поиске ключа хоста. Используйте параметр, когда на одном хосте работает несколько серверов или для SSH-туннелирования.

#### HostName

Параметр **`HostName`** содержит фактическое имя хоста для входа. Значение по умолчанию — имя хоста, переданное в командной строке. Используйте параметр, чтобы указывать псевдонимы, сокращения или числовые IP-адреса.

![The HostName parameter in the ssh config file.](/images/5154fea48870c5c5ff8cfdc59f11dc7d.png)

#### IdentitiesOnly

Параметр **`IdentitiesOnly`** указывает использовать только файлы идентичности, заданные в _ssh_config_. По умолчанию значение — **`no`**. Используйте параметр, когда **ssh-agent** предлагает несколько идентичностей.

#### IdentityFile

Параметр **`IdentityFile`** содержит путь к файлу идентичности с RSA- или DSA-идентичностью пользователя. Путь по умолчанию для протокола версии 1 — _~/.ssh/identity_, тогда как протокол версии 2 использует _~/.ssh/id_rsa_ или _~/.ssh/id_dsa_.

Путь к файлу идентичности позволяет использовать тильду (**~**) для домашнего каталога пользователя и следующие подстановки:

* **`%d`** — домашний каталог локального пользователя.
* **`%u`** — имя локального пользователя.
* **`%l`** — локальное имя хоста.
* **`%h`** — удалённое имя хоста.
* **`%r`** — удалённое имя пользователя.

Параметр позволяет использовать несколько файлов идентичности, применяемых в указанном порядке.

#### KbdInteractiveAuthentication

Параметр **`KbdInteractiveAuthentication`** контролирует, использовать ли интерактивный режим клавиатуры для аутентификации. Значение параметра по умолчанию — **`yes`**.

#### KbdInteractiveDevices

Параметр **`KbdInteractiveDevices`** содержит список методов для использования с keyboard-interactive аутентификацией. Список значений по умолчанию зависит от типа сервера. Например, сервер OpenSSH использует ноль или более из следующих: **`bsdauth`**, **`pam`** и **`skey`**.

#### LocalCommand

Параметр **`LocalCommand`** позволяет выполнить команду на локальной машине после успешного подключения по SSH. Строка команды выполняется в shell пользователя.

Чтобы разрешить выполнение команды, включите параметр **`PermitLocalCommand`**.

![The LocalCommand parameter in the ssh config file.](/images/8f95389c5f9426ed301873da876d7a65.png)

#### LocalForward

Параметр **`LocalForward`** указывает локальный порт для перенаправления через защищённый канал на целевой хост и порт на удалённой машине. Параметр требует двух аргументов:

* **`bind_address:port`** для IPv4 или **`bind_address/port`** для IPv6-адресов. Адрес привязки опционален.
* **`host:hostport`** для IPv4 или **`host/hostport`** для IPv6-адресов.

Для нескольких портов укажите несколько аргументов или передайте дополнительную информацию о перенаправлении через командную строку.

#### LogLevel

Параметр **`LogLevel`** контролирует детализацию вывода сообщений SSH. Доступные опции:

```text
QUIET, FATAL, ERROR, INFO, VERBOSE, DEBUG, DEBUG1, DEBUG2, and DEBUG3
```

Аргумент **`INFO`** — значение по умолчанию, тогда как **`DEBUG`** и **`DEBUG1`** обозначают один уровень.

#### MACs

Параметр **`MACs`** позволяет перечислить алгоритмы аутентификации сообщений (MAC) для протокола версии 2. Алгоритмы определяют алгоритм защиты целостности данных. Возможные значения:

```text
hmac-md5, hmac-sha1, umac-64@openssh.com,
hmac-ripemd160, hmac-sha1-96, hmac-md5-96
```

Указывайте несколько алгоритмов списком через запятую. Алгоритмы применяются в указанном порядке.

#### NoHostAuthenticationForLocalhost

Параметр **`NoHostAuthenticationForLocalhost`** отключает аутентификацию для localhost. Значение по умолчанию — **`no`**, то есть проверка ключа хоста выполняется для localhost.

Включите опцию, чтобы разрешить использование домашнего каталога на нескольких машинах. Предупреждения об изменённых ключах хоста будут появляться, поскольку «localhost» на каждой машине означает разные устройства.

#### NumberOfPasswordPrompts

Параметр **`NumberOfPasswordPrompts`** позволяет указать, сколько раз запрашивать пароль при неудаче. Аргумент параметра — целое число, по умолчанию **`3`**.

![The NumberOfPasswordPrompts parameter in the ssh config file.](/images/5b21d90e56708fb37775017f26e61635.png)

#### PasswordAuthentication

Параметр **`PasswordAuthentication`** контролирует, должна ли быть аутентификация по паролю. Значение параметра по умолчанию — **`yes`**.

#### PermitLocalCommand

Опция **`PermitLocalCommand`** контролирует, выполнит ли параметр **`LocalCommand`** команду на локальной машине после подключения. По умолчанию параметр выключен со значением **`no`**.

#### Port

Параметр **`Port`** содержит номер порта на удалённом хосте. Порт SSH по умолчанию — номер порта **`22`**.

#### PreferredAuthentications

Параметр **`PreferredAuthentications`** — список методов аутентификации, которые клиент использует в порядке предпочтения. Список содержит методы аутентификации протокола версии 2, возможные значения:

```text
gssapi-with-mic, hostbased, publickey, keyboard-interactive, password
```

Изменение порядка также меняет предпочтения аутентификации клиента.

#### Protocol

Параметр **`Protocol`** содержит предпочитаемую версию протокола SSH. Возможные значения — **`1`** и **`2`**. Перечисляйте значения в порядке предпочтения как запасной вариант, если первый не сработает.

#### ProxyCommand

Параметр **`ProxyCommand`** задаёт команду для подключения к серверу; аргумент — строка команды, выполняемая в shell пользователя.

Команда должна подключаться к серверу демона OpenSSH, работающему на машине, или выполнять **`sshd -i`**. Например, используйте Netcat для подключения к HTTP-прокси следующим образом:

```text
ProxyCommand nc -X connect -x <address>:<port> %h %p
```

[Команда nc](https://phoenixnap.com/kb/nc-command) содержит поддержку прокси и работает с параметром **`ProxyCommand`** для подключения через прокси. Параметр **`%h`** подставляет хост, тогда как **`%p`** — номер порта.

#### PubkeyAuthentication

Параметр **`PublicKeyAuthentication`** контролирует, использовать ли аутентификацию по публичному ключу. Значение по умолчанию — **`no`** и работает только для протокола версии 2.

#### RekeyLimit

Параметр **`RekeyLimit`** задаёт максимальный объём данных для передачи перед пересогласованием ключей. Значение аргумента — количество [байт](https://phoenixnap.com/glossary/what-is-a-byte) с суффиксами [килобайт](https://phoenixnap.com/glossary/kilobyte-definition) (**`K`**), мегабайт (**`M`**) и [гигабайт](https://phoenixnap.com/glossary/gigabyte-definition) (**`G`**).

В зависимости от шифра значение по умолчанию — между **`1G`** и **`4G`**.

#### RemoteForward

Параметр **`RemoteForward`** определяет TCP-порт на удалённой машине для перенаправления через защищённое соединение. Укажите следующие два аргумента:

* **`bind_address:port`** для IPv4 или **`bind_address/port`** для IPv6-адресов. Адрес привязки опционален.
* **`host:hostport`** для IPv4 или **`host/hostport`** для IPv6-адресов.

Для использования нескольких портов укажите несколько аргументов или передайте дополнительную информацию через командную строку.

#### RhostsRSAAuthentication

Параметр **`RhostRSAAuthentication`** задаёт, использовать ли аутентификацию на основе RHOST и RSA-аутентификацию хоста. Доступные опции: **`yes`** или **`no`** (по умолчанию).

#### RSAAuthentication

Параметр **`RSAAuthentication`** контролирует, пробовать ли RSA-аутентификацию. Параметр применяется только к протоколу версии 1, значение по умолчанию — **`yes`**. Попытка RSA-аутентификации происходит, только если существует файл идентичности или запущен агент аутентификации.

#### SendEnv

Параметр **`SendEnv`** содержит переменные окружения для отправки из локального окружения на сервер. Настройте сервер принимать переменные окружения через параметр **`AcceptEnv`** в файле _/etc/ssh/sshd_config_.

По умолчанию никакие переменные не отправляются. Чтобы отправить несколько переменных окружения, используйте **`SendEnv`** несколько раз или передайте список имён переменных через запятую.

#### ServerAliveCountMax

Параметр **`ServerAliveCountMax`** задаёт максимальное число сообщений о живости сервера (по умолчанию 3). Сессия завершается, когда соединение достигает порога, определяемого как **`ServerAliveInterval`** * **`ServerAliveCountMax`**, в секундах.

Сообщения помогают клиенту и серверу узнать, когда соединение неактивно.

#### ServerAliveInterval

Параметр **`ServerAliveInterval`** — интервал таймаута в секундах, в течение которого от сервера не приходит данных. По истечении интервала SSH отправляет зашифрованный запрос на ответ серверу. Значение параметра по умолчанию — **`0`**, то есть SSH не отправляет серверу сообщений.

#### SmartcardDevice

Параметр **`SmartcardDevice`** контролирует, какое устройство смарт-карты использовать. Поддержка смарт-карт по умолчанию неактивна. Если активна, аргумент по умолчанию — публичные ключи SSH со смарт-карты.

#### StrictHostKeyChecking

Параметр **`StrictHostKeyChecking`** указывает, автоматически ли добавлять ключи хостов в файл _~/.ssh/known_hosts_ при изменениях. Опции по умолчанию: **`yes`**, **`no`** или **`ask`** (по умолчанию). Проверка — хорошая мера безопасности против атак «троянский конь».

#### TCPKeepAlive

Параметр **`TCPKeepAlive`** отправляет TCP-сообщения серверу для проверки связности. Если сеть недоступна или сервер упал, клиент получает информацию через TCP-сообщения.

По умолчанию сообщения установлены в **`yes`**. Отключите параметр, чтобы избежать разрыва соединения при временных сбоях маршрутов.

#### Tunnel

Параметр **`Tunnel`** запрашивает устройство туннельного интерфейса для перенаправления между клиентом и сервером. Доступные опции: **`yes`**, **`point-to-point`**, **`ethernet`** или **`no`** (по умолчанию). Опция туннеля для **`yes`** — **`point-to-point`**.

#### TunnelDevice

Параметр **`TunnelDevice`** помогает определить, какие устройства открывать на клиенте (локальное туннелирование) и сервере (удалённое туннелирование). Аргумент — **`local:remote`**, значениями которого являются ID устройств или **`any`**. ID удалённого устройства опционален и по умолчанию **`any`**, если опущен.

Значение по умолчанию для туннельного устройства — **`any:any`**, и в обоих случаях используется следующее доступное устройство.

#### UsePrivilegedPort

Параметр **`UserPrivilegedPort`** определяет, использовать ли привилегированный порт для внешних соединений. Возможные значения: **`yes`** или **`no`** (по умолчанию). Если используется **`RhostsRSAAuthentication`** со старыми серверами, установите значение параметра **`yes`**.

#### User

При установлении соединения параметр **`User`** задаёт имя пользователя для входа. Используйте опцию, когда имя пользователя различается на машинах, или чтобы не указывать его в командной строке.

#### UserKnownHostsFile

Параметр **`UserKnownHostsFile`** задаёт путь к файлу известных хостов. Расположение по умолчанию — _~/.ssh/known_hosts_.

#### VerifyHostKeyDNS

Параметр **`VerifyHostKeyDNS`** определяет, использовать ли DNS и записи SSHFP для проверки удалённого ключа. Значение по умолчанию — **`no`**; изменив его на **`yes`**, вы автоматически включите доверие ключам, совпадающим с DNS-отпечатком. Используйте опцию **`ask`**, чтобы отображать совпадения отпечатков и требовать подтверждения.

#### VisualHostKey

Параметр **`VisualHostKey`** контролирует, выводить ли ASCII-арт [отпечатка ключа](https://phoenixnap.com/glossary/public-key-fingerprint) удалённого хоста для неизвестных ключей хоста. По умолчанию значение — **`no`**, и для неизвестных ключей хоста выводится только hex-строка отпечатка.

#### XAuthLocation

Параметр **`XAuthLocation`** хранит полный путь к утилите X authority. Расположение по умолчанию — _/usr/bin/xauth_.
