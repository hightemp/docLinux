![Using Lock Files for Job Control in Bash Scripts](/images/636ff67abad97b038dd9b795005cde2b.png)

Продолжая нашу серию туториалов по Bash, я подумал, что было бы хорошо обсудить lock-файлы. Самое частое применение lock-файлов — гарантировать, что второй экземпляр скрипта не запустится, пока не завершится первый. Везде, где несколько процессов работают с разделяемыми ресурсами, lock-файлы помогут избежать конфликтов и состояний гонки (race conditions).

Важно отметить, что lock-файлы используются во многих языках программирования. В этом туториале мы будем обсуждать их применение в shell-скриптах. Однако мы уверены, что эта информация легко переносима и на другие языки.

Вот реальный пример того, как можно использовать lock-файлы. Мой коллега написал скрипт, который с помощью [rsync поверх ssh синхронизирует](https://www.putorius.net/using-rsync-to-synchronize-directories.html) домашний каталог своей рабочей станции с разделяемым каталогом на сервере. Он настроил cron на запуск этого скрипта каждый час. Первый месяц всё было нормально, но однажды он скопировал в свой домашний каталог кучу журналов и несколько больших ISO-файлов. Этот наплыв данных привёл к тому, что rsync-скрипт работал дольше часа. Не успев завершиться, cron запустил второй экземпляр скрипта. Это замедлило копирование, что привело к запуску третьего экземпляра, затем четвёртого и так далее. Не успел он опомниться, как его рабочая станция стала непригодной для работы. Использование lock-файла могло бы помочь избежать этого сценария.

В этом туториале мы обсудим основы использования lock-файлов. Мы рассмотрим создание базового lock-файла, а также использование утилиты flock для управления lock-файлами и организации очередей.

## Создание базового lock-файла

Базовый lock-файл — это когда вы создаёте файл, используемый в качестве блокировки. Существование файла служит сигналом для любого последующего экземпляра скрипта не запускаться. Когда скрипт завершается, вы удаляете файл. Следующий экземпляр скрипта проверяет наличие файла, чтобы определить, безопасно ли выполняться.

Вот пример кода:

```bash
#!/bin/bash
# Check is Lock File exists, if not create it and set trap on exit
if { set -C; 2>/dev/null >~/manlocktest.lock; }; then
    trap "rm -f ~/manlocktest.lock" EXIT
else
    echo "Lock file exists… exiting"
    exit
fi
# Do Something, Main script work here…
echo "I am a script and I am doing something… anything…"
sleep 30
```

_Спасибо Дэвиду за обновлённый код._

В приведённом примере мы используем простой оператор if, чтобы проверить, существует ли файл. Если файл существует, скрипт завершается (не удалось получить блокировку). Если файла НЕ существует, он создаёт файл и [trap для удаления файла при выходе](https://www.putorius.net/using-trap-to-exit-bash-scripts-cleanly.html), а затем продолжает работу.

Вот наш скрипт в действии. Я запущу скрипт и отправлю его в фон. Затем я попробую запустить скрипт ещё раз — в этот момент он должен завершиться, потому что lock-файл существует.

[![Анимированный gif, показывающий, как работает простой lock-файл в shell-скриптинге на bash.](/images/82846f67e8c1467d4058f734b5c2b7b2.png)](https://www.putorius.net/wp-content/uploads/2019/05/manlocktest-min.gif.webp)

Вот вам простая блокировка. Если скрипт запускается второй раз и видит, что файл создан, он завершится.

ПРИМЕЧАНИЕ: по моему мнению, важно использовать trap для удаления файла, а не просто `rm <filename>` в конце скрипта. Мы подробно говорили о преимуществах использования trap в статье «[Using Trap to Exit Bash Scripts Cleanly](https://www.putorius.net/using-trap-to-exit-bash-scripts-cleanly.html)».

## Использование flock для создания lock-файлов

Flock — это имя и системного вызова уровня ядра, и утилиты командной строки. Последняя — просто способ управлять системными вызовами из shell-скриптов или командной строки.

Команда flock работает с файловыми дескрипторами, а не с файлами. Файловый дескриптор — уникальный номер, используемый для доступа к ресурсу данных. Самые популярные файловые дескрипторы — 1 (стандартный ввод), 2 (стандартный вывод) и 3 (стандартный вывод ошибок). Они были описаны в статье «[Introduction to Linux IO, Standard Streams, and Redirection](https://www.putorius.net/linux-io-file-descriptors-and-redirection.html)».

> В Unix и родственных операционных системах файловый дескриптор (FD, реже fildes) — это абстрактный индикатор (дескриптор), используемый для доступа к файлу или другому ресурсу ввода-вывода, такому как пайп или сетевой сокет. Файловые дескрипторы являются частью прикладного программного интерфейса POSIX.
>
> — WikiPedia

### Использование flock для организации очереди заданий

Одно из главных преимуществ использования flock перед простым lock-файлом — возможность ставить задания в очередь, то есть ждать блокировку. По умолчанию flock будет ждать блокировку бесконечно, если вы не используете опцию -n (nonblock).

Вот код, который мы будем использовать как тестовый скрипт.

```bash
#!/bin/bash
exec 100>/var/tmp/testlock.lock || exit 1
flock 100 || exit 1

echo "Doing some stuff…"
echo "Sleeping for 30 seconds…"
sleep 30
```

Давайте подробнее рассмотрим две важные строки, из которых состоит блокировка.

```bash
exec 100>/var/tmp/testlock.lock || exit 1
```

Это перенаправляет файловый дескриптор 100 в нужный lock-файл. Использование [exec](https://www.putorius.net/exec-command.html) гарантирует, что перенаправление доступно на протяжении всей жизни shell. «|| exit 1» указывает скрипту завершиться, если команда exec не удалась.

```bash
flock 100 || exit 1
```

Вышеприведённая строка получает блокировку файлового дескриптора 100. По сути, удерживает блокировку файла, пока shell не закроется. Поскольку скрипты выполняются в подоболочке, файл будет закрыт (или разблокирован) при завершении скрипта. «|| exit 1» указывает скрипту завершиться, если блокировку не удалось получить.

Вот и всё — мы только что создали файловую блокировку с помощью flock. Всё довольно просто, как только вы уложите это в голове.

### Использование ожидания или таймаута для заданий в очереди

У вас также есть возможность ждать _x_ секунд для получения блокировки, прежде чем потерпеть неудачу.

Возьмём такой пример.

```bash
#!/bin/bash
exec 100>/var/tmp/testlock.lock || exit 1
flock -w 10 100 || exit 1

echo "Doing some stuff…"
echo "Sleeping for 5 seconds…"
sleep 5
```

Здесь мы используем опцию -w (wait) для flock и задаём ей значение 10. Это указывает flock потерпеть неудачу, если блокировку не удастся получить за 10 секунд. Поскольку скрипт должен выполняться всего 5-6 секунд, мы должны получить блокировку до истечения таймаута. Давайте проверим.

[![Анимированный gif, показывающий использование flock для постановки задания в очередь с опцией wait](/images/9f385a1f0cab1ef17a329b049ce10fc3.png)](https://www.putorius.net/wp-content/uploads/2019/05/flockwait-min.gif.webp)

Как видите в примере выше, flock дождался, пока скрипт освободит блокировку. Затем второй экземпляр скрипта получил блокировку и выполнился.

Таймауты — хороший способ убедиться, что у вас не скапливается куча скриптов, ждущих, пока какой-нибудь зависший ресурс не освободит блокировку.

### Не ставить задания в очередь при использовании flock

Как мы упоминали выше, поведение flock по умолчанию — ждать блокировку бесконечно. Мы также обсудили использование опции -w (timeout) для установки ограничения на время ожидания. Наоборот, вы можете использовать опцию -n (nonblock), чтобы мгновенно потерпеть неудачу, если блокировку нельзя получить немедленно.

Пример кода:

```bash
#!/bin/bash
exec 100>/var/tmp/testlock.lock || exit 1
flock -n 100 || exit 1
echo "Doing some stuff…"
echo "Sleeping for 10 seconds…"
sleep 10
```

Ниже вы увидите, что я отправляю первый экземпляр скрипта test.sh в фон. Затем я пытаюсь запустить второй экземпляр — и он мгновенно завершается с ошибкой, вместо того чтобы ждать блокировку.

[![Анимированный gif, показывающий использование команды flock с опцией nonblock](/images/c9c8f97ab97a77b57abdde33722d190f.png)](https://www.putorius.net/wp-content/uploads/2019/05/flocknb-min.gif.webp)

Кроме того, можно задать -E (conflict-exit-code), чтобы использовать пользовательский код выхода. Эта опция используется только вместе с опцией nonblock или опцией timeout, поскольку в противном случае flock ждал бы блокировку бесконечно.

### Эксклюзивная блокировка против разделяемой

Существует два вида блокировок: эксклюзивная (exclusive, она же блокировка записи) и разделяемая (shared, она же блокировка чтения).

* Если взята эксклюзивная блокировка, ни один другой процесс не может взять блокировку — ни эксклюзивную, ни разделяемую — на этот файл.
* Если взята разделяемая блокировка, другие процессы могут взять разделяемую блокировку на этот же файл, но ни один процесс не может взять эксклюзивную блокировку.

Утилита flock в Linux по умолчанию берёт эксклюзивную блокировку. Свое желание получить разделяемую блокировку нужно указывать явно с помощью опции -s (shared).

### Очистка lock-файлов flock

Удалять lock-файлы, созданные при использовании flock, не обязательно, поскольку flock не использует существование файла как индикатор. Однако поддерживать файловую систему в порядке — наверняка хорошая идея.

Вы можете использовать trap для удаления lock-файлов, точно так же, как мы делали с базовым lock-файлом.

```bash
#!/bin/bash
exec 100>/var/tmp/testlock.lock || exit 1
flock -n 100 || exit 1
trap 'rm -f /var/tmp/testlock.lock' EXIT

# Main script actions here
```
