**********

Потоки — это весело!

Умение правильно использовать потоки должно быть частью арсенала каждого студента, изучающего компьютерные науки и инженерию. Это руководство — попытка помочь вам познакомиться с многопоточным программированием с помощью потоков POSIX (Portable Operating System Interface), или pthreads. Это руководство объясняет различные инструменты, определённые в библиотеке pthread, показывает, как их использовать, и приводит примеры их применения для решения реальных задач программирования.

**********

Что такое потоки?

Технически поток определяется как независимый поток инструкций, который операционная система может планировать к выполнению как таковой.

Поток — это полупроцесс, имеющий собственный стек и выполняющий заданный участок кода. В отличие от настоящего процесса, поток обычно разделяет свою память с другими потоками (тогда как для процессов у нас, как правило, своя область памяти для каждого из них). Группа потоков (Thread Group) — это набор потоков, все выполняющихся внутри одного процесса. Все они разделяют одну и ту же память и, следовательно, могут обращаться к одним и тем же глобальным переменным, одной и той же куче, одному и тому же набору файловых дескрипторов и т.д. Все эти потоки выполняются параллельно (т.е. используя кванты времени, а если в системе несколько процессоров — то по-настоящему параллельно).

**********

Что такое pthreads? Исторически производители аппаратного обеспечения реализовывали свои собственные проприетарные версии потоков. Эти реализации существенно отличались друг от друга, что затрудняло разработку переносимых многопоточных приложений. Чтобы в полной мере воспользоваться возможностями, предоставляемыми потоками, требовался стандартизированный программный интерфейс. Для систем UNIX этот интерфейс специфицирован стандартом IEEE POSIX 1003.1c (1995). Реализации, соответствующие этому стандарту, называются потоками POSIX, или Pthreads. Большинство производителей оборудования теперь предлагают Pthreads в дополнение к своим проприетарным потокам.

**********

Потоки эффективны… Если реализованы правильно, потоки имеют ряд преимуществ перед процессами. По сравнению со стандартным fork(), потоки несут гораздо меньше накладных расходов. Помните, что fork() создаёт вторую копию вызывающего процесса. Родитель и потомок **_полностью независимы_**, каждый со своим адресным пространством, со своими копиями переменных, которые совершенно независимы от тех же переменных в другом процессе. Потоки разделяют общее адресное пространство, избегая тем самым многих неэффективностей множества процессов.

* Ядру не нужно создавать новую независимую копию памяти процесса, файловых дескрипторов и т.д. Это экономит много процессорного времени, делая создание потока в десять-сто раз быстрее создания нового процесса. Благодаря этому можно использовать целую кучу потоков и не беспокоиться о накладных расходах CPU и памяти. Это значит, что вы, как правило, можете создавать потоки всегда, когда это имеет смысл в вашей программе.
* Меньше времени на завершение потока, чем процесса.
* Переключение контекста между потоками намного быстрее, чем переключение контекста между процессами (переключение контекста означает, что система переключается с выполнения одного потока или процесса на выполнение другого потока или процесса).
* Меньше накладных расходов на коммуникацию — взаимодействие между потоками одного процесса просто, потому что потоки разделяют адресное пространство. Данные, произведённые одним потоком, немедленно доступны всем остальным потокам.

С другой стороны, поскольку потоки в группе все используют одно и то же пространство памяти, если один из них испортит содержимое своей памяти, могут пострадать и другие потоки. С процессами операционная система обычно защищает процессы друг от друга, и потому, если один испортит своё собственное пространство памяти, другие процессы не пострадают.

**********

Потоки полезны — примеры приложений. **Пример 1: отзывчивый пользовательский интерфейс.** Одна из областей, где потоки могут быть очень полезны, — программы с пользовательским интерфейсом. Эти программы обычно построены вокруг цикла чтения пользовательского ввода, его обработки и отображения результатов обработки. Часть обработки иногда может занять какое-то время, и пользователю приходится ждать во время этой операции. Поместив такие длительные операции в отдельный поток и имея другой поток для чтения пользовательского ввода, программа может стать более отзывчивой. Она может позволить пользователю отменить операцию в середине. **Пример 2: графический интерфейс.** В графических программах проблема стоит острее, поскольку приложение всегда должно быть готово к сообщению от оконной системы с требованием перерисовать часть своего окна. Если оно слишком занято выполнением какой-то другой задачи, его окно останется пустым, что довольно некрасиво. В таком случае хорошая идея — иметь один поток, обрабатывающий цикл сообщений оконной системы и всегда готовый получать такие запросы перерисовки (а также пользовательский ввод). Всякий раз, когда этот поток видит необходимость выполнить операцию, которая может занять долгое время (скажем, больше 0.2 секунды в худшем случае), он делегирует работу отдельному потоку. **Пример 3: веб-сервер**

* Ему нужно обработать несколько запросов на скачивание за короткий период
* Следовательно, эффективнее создавать (и уничтожать) по одному потоку на каждый запрос
* Несколько потоков могут потенциально выполняться одновременно на разных процессорах

**********

Создание и уничтожение потоков. Когда многопоточная программа начинает выполняться, в ней работает один поток, который выполняет функцию main() программы. Это уже полноценный поток со своим собственным идентификатором. Чтобы создать новый поток, программа должна использовать функцию `[pthread_create()](http://pubs.opengroup.org/onlinepubs/007908775/xsh/pthread_create.html)`. Вот как ею пользоваться:

**********

```c
#include <stdio.h>       /* standard I/O routines                 */
#include <pthread.h>     /* pthread functions and data structures */

/* function to be executed by the new thread */
void* PrintHello(void* data)
{
    int my_data = (int)data;         /* data received by thread */

    [pthread_detach](http://pubs.opengroup.org/onlinepubs/009695399/functions/pthread_detach.html)([pthread_self](http://pubs.opengroup.org/onlinepubs/009695399/functions/pthread_self.html)());
    printf("Hello from new thread - got %d\n", my_data);
    [pthread_exit](http://pubs.opengroup.org/onlinepubs/007908775/xsh/pthread_exit.html)(NULL);      /* terminate the thread */
}

/* like any C program, program's execution begins in main */
int main(int argc, char* argv[])
{
    int        rc;              /* return value                           */
    pthread_t  thread_id;       /* thread's ID (just an integer)          */
    int        t         = 11;  /* data passed to the new thread          */

    /* create a new thread that will execute 'PrintHello' */
    rc = [pthread_create](http://pubs.opengroup.org/onlinepubs/007908775/xsh/pthread_create.html)(&thread_id, NULL, PrintHello, (void*)t);
    if(rc)          /* could not create thread */
    {
        printf("\n ERROR: return code from pthread_create is %d \n", rc);
        exit(1);
    }
    printf("\n Created new thread (%u) ... \n", thread_id);

    [pthread_exit](http://pubs.opengroup.org/onlinepubs/007908775/xsh/pthread_exit.html)(NULL);      /* terminate the thread */
}
```

**********

Разберём простую многопоточную программу выше. Хотя она не делает ничего полезного, она поможет вам понять, как работают потоки. Давайте шаг за шагом посмотрим, что делает программа.

1. В `main()` мы объявляем переменную с именем `thread_id` типа `pthread_t`. Это по сути целое число, используемое для идентификации потока в системе. После объявления `thread_id` мы вызываем функцию `[pthread_create](http://pubs.opengroup.org/onlinepubs/007908775/xsh/pthread_create.html)`, чтобы создать настоящий, живой поток.
2. `[pthread_create()](http://pubs.opengroup.org/onlinepubs/007908775/xsh/pthread_create.html)` принимает 4 аргумента. Первый аргумент — указатель на `thread_id`, используемый `pthread_create()`, чтобы снабдить программу идентификатором потока. Второй аргумент используется для установки некоторых атрибутов нового потока. В нашем случае мы передали NULL-указатель, чтобы сказать `pthread_create()` использовать значения по умолчанию. Обратите внимание, что `PrintHello()` принимает `void *` в качестве аргумента и также возвращает `void *` в качестве возвращаемого значения. Это показывает, что можно использовать `void *`, чтобы передать произвольный кусок данных нашему новому потоку, и что наш новый поток может вернуть произвольный кусок данных по завершении. Как передать нашему потоку произвольный аргумент? Просто. Используем четвёртый аргумент вызова `pthread_create()`. Если мы не хотим передавать никакие данные новому потоку, устанавливаем четвёртый аргумент в NULL. `pthread_create()` возвращает ноль при успехе и ненулевое значение при неудаче.
3. После успешного возврата `pthread_create()` программа будет состоять из двух потоков. Это потому, что главная программа — тоже поток, и она выполняет код в функции `main()` параллельно с потоком, который она создала. Подумайте об этом так: если вы пишете программу, которая вообще не использует потоки POSIX, программа будет однопоточной (этот единственный поток называется «главным» потоком).
4. Вызов `[pthread_exit](http://pubs.opengroup.org/onlinepubs/007908775/xsh/pthread_exit.html)` заставляет текущий поток завершиться и освободить все специфичные для потока ресурсы, которые он занимает.

Чтобы скомпилировать многопоточную программу с помощью `gcc`, нам нужно слинковать её с библиотекой pthreads. Предполагая, что эта библиотека уже установлена в вашей системе, вот как скомпилировать нашу первую программу:

```bash
gcc hello.c -o hello -lpthread
```

Исходный код этой программы можно найти в файле [hello.c](./hello.txt).

_Упражнение 2_. Поток может получить свой собственный идентификатор, вызвав `[pthread_self](http://pubs.opengroup.org/onlinepubs/009695399/functions/pthread_self.html)()`, который возвращает идентификатор потока:

```c
pthread_t pthread_self();
```

Используйте его так:

```c
pthread_t tid;
tid = pthread_self();
```

Модифицируйте код `hello.c`, чтобы печатать идентификатор обоих потоков. Обязательно используйте спецификатор формата `%u` (без знака) для вывода идентификатора потока. На Linux-машинах идентификаторы потоков — обычно очень большие значения, которые выглядят отрицательными, если не интерпретировать их как целые без знака. Перекомпилируйте и запустите исполняемый файл `hello`. Новый вывод должен быть примерно таким:

```text
I am thread 1. Created new thread (4) ...
Hello from new thread 4 - got 11
```

Если вы запустите код на Linux-машине, идентификатор нового потока будет очень большим целым числом, а не 4 (как показано здесь). Теперь модифицируйте код так, чтобы главный поток передавал свой собственный идентификатор новому создаваемому потоку. Перекомпилируйте и запустите исполняемый файл `hello`. Вывод должен быть примерно таким:

```text

```

_Упражнение 3_. Существует несколько способов завершения потоков. Один безопасный способ — вызвать процедуру `[pthread_exit](http://pubs.opengroup.org/onlinepubs/007908775/xsh/pthread_exit.html)` (эквивалент `exit` для процессов). В этом упражнении модифицируйте вашу программу `hello.c` следующим образом.

* В процедуре `PrintHello` добавьте строку

```c
sleep(1);
```

перед вызовом `printf`. Это заставляет вызывающий поток заснуть на 1 секунду и затем продолжить выполнение (мы пытаемся заставить этот поток завершиться после главного). Используйте справочные страницы Unix, чтобы выяснить, какие заголовочные файлы нужны для функции `sleep` (пробуйте разделы man 2, 3 и т.д., пока не найдёте нужное определение).
* В функции `main` закомментируйте последнюю строку, содержащую вызов `pthread_exit`.

Перекомпилируйте и запустите исполняемый файл `hello`. **Что происходит? Почему?** Затем верните вызов `pthread_exit` в главную программу, но уберите его из процедуры `PrintHello`. Также добавьте вызов `sleep` в главную процедуру, прямо перед вторым вызовом `printf`, и уберите его из `PrintHello` (теперь главный поток завершается последним). Перекомпилируйте и запустите исполняемый файл `hello`. **Что происходит? Почему?** _Необходимо использовать `pthread_exit` в конце главной программы. Иначе при её выходе все работающие потоки будут убиты._

_Упражнение 4_. Функция `[pthread_join](http://pubs.opengroup.org/onlinepubs/009695399/functions/pthread_join.html)()` для потоков — эквивалент `wait` для процессов. Вызов `[pthread_join](http://pubs.opengroup.org/onlinepubs/009695399/functions/pthread_join.html)` блокирует вызывающий поток до завершения потока с идентификатором, равным первому аргументу.

```c
#include <stdio.h>       /* standard I/O routines                 */
#include <pthread.h>     /* pthread functions and data structures */

void* PrintHello(void* data)
{
    pthread_t tid = (pthread_t)data;    /* data received by thread */

    pthread_join(tid, NULL);            /* wait for thread tid     */
    printf("Hello from new thread %u - got %u\n", pthread_self(), data);
    pthread_exit(NULL);                 /* terminate the thread    */
}

/* like any C program, program's execution begins in main */
int main(int argc, char* argv[])
{
    int        rc;                      /* return value                  */
    pthread_t  thread_id;               /* thread's ID (just an integer) */
    int        tid;

    tid = pthread_self();

    rc = pthread_create(&thread_id, NULL, PrintHello, (void*)tid);
    if(rc)                             /* could not create thread */
    {
        printf("\n ERROR: return code from pthread_create is %d \n", rc);
        exit(1);
    }
    sleep(1);
    printf("\n Created new thread (%u) ... \n", thread_id);
    pthread_exit(NULL);
}
```

Первый аргумент `pthread_join()` — идентификатор потока, к которому присоединяемся. Второй аргумент — указатель void.

```c
pthread_join(pthread_t tid, void * return_value);
```

Если указатель `return_value` не NULL, `pthread_join` поместит по адресу памяти, на который указывает `return_value`, значение, переданное потоком `tid` через вызов `pthread_exit`. Поскольку нам безразлично возвращаемое значение главного потока, мы устанавливаем его в NULL. Перекомпилируйте и запустите исполняемый файл с приведённым выше кодом. Вывод такой, как вы ожидали?

**********

Примечание. В любой момент времени поток находится либо в состоянии присоединяемого (joinable), либо отсоединённого (detached) — по умолчанию состояние joinable. _Присоединяемые_ потоки должны быть «собраны» или убиты другими потоками (с помощью `pthread_join`), чтобы освободить ресурсы памяти. _Отсоединённые_ потоки не могут быть собраны или убиты другими потоками, и ресурсы освобождаются автоматически при завершении. Так что если только потокам не нужно синхронизироваться между собой, лучше вызывать

```c
pthread_detach(pthread_self());
```

вместо `pthread_join`.
