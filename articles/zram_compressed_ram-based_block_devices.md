# zram: сжатые блочные устройства в оперативной памяти

Источник: [zram: Compressed RAM-based block devices](https://docs.kernel.org/admin-guide/blockdev/zram.html)

Nitin Gupta (ngupta@vflare.org)

## Введение

Модуль zram создаёт блочные устройства в оперативной памяти с именами /dev/zram<id> (<id> = 0, 1, ...). Страницы, записываемые на эти диски, сжимаются и хранятся прямо в памяти. Эти диски обеспечивают очень быстрый ввод-вывод, а сжатие даёт заметную экономию памяти. Некоторые сценарии использования: хранилище /tmp, использование в качестве swap-дисков, различные кэши в /var и, возможно, многое другое. :)

Статистика по отдельным устройствам zram экспортируется через узлы sysfs по пути /sys/block/zram<id>/

## Использование

Существует несколько способов настройки и управления устройствами zram:

  1. с использованием атрибутов sysfs zram и zram_control

  2. с использованием утилиты zramctl из util-linux ([util-linux@vger.kernel.org](mailto:util-linux%40vger.kernel.org)).

В этом документе мы опишем только шаги «ручной» настройки zram, то есть атрибуты sysfs zram и zram_control.

Чтобы лучше узнать о zramctl, обратитесь к документации util-linux, man-странице zramctl или zramctl --help. Обратите внимание, что мейнтейнеры zram не разрабатывают и не поддерживают util-linux или zramctl; при возникновении вопросов обращайтесь к [util-linux@vger.kernel.org](mailto:util-linux%40vger.kernel.org).

Далее показана типичная последовательность шагов для использования zram.

## ПРЕДУПРЕЖДЕНИЕ

Ради простоты в большинстве примеров ниже мы пропускаем проверку ошибок. Однако обработка ошибок — целиком ваша ответственность.

Атрибуты sysfs zram в случае ошибок всегда возвращают отрицательные значения. Список возможных кодов возврата:

-EBUSY | попытка изменить атрибут, который нельзя менять после инициализации устройства. Сначала сбросьте устройство.
---|---
-ENOMEM | zram не смог выделить достаточно памяти для удовлетворения вашего запроса.
-EINVAL | предоставлен некорректный ввод.
-EAGAIN | повторите операцию позже (например, при попытке одновременно запустить recompress и writeback).

Если вы используете ‘echo’, возвращаемое значение устанавливается утилитой ‘echo’, и в общем случае достаточно чего-то вроде:

```bash
echo foo > /sys/block/zram0/comp_algorithm
if [ $? -ne 0 ]; then
        handle_error
fi
```

## Загрузка модуля

```bash
modprobe zram num_devices=4
```

Это создаёт 4 устройства: /dev/zram{0,1,2,3}

Параметр num_devices необязателен и говорит zram, сколько устройств нужно создать заранее. По умолчанию: 1.

## Выбор алгоритма сжатия

С помощью атрибута устройства comp_algorithm можно увидеть доступные и выбранные в данный момент (показаны в квадратных скобках) алгоритмы сжатия, либо сменить выбранный алгоритм сжатия (после инициализации устройства сменить алгоритм сжатия невозможно).

Примеры:

```bash
#show supported compression algorithms
cat /sys/block/zram0/comp_algorithm
lzo [lz4]
```

```bash
#select lzo compression algorithm
echo lzo > /sys/block/zram0/comp_algorithm
```

В настоящее время содержимое comp_algorithm показывает только те алгоритмы сжатия, которые поддерживает zram.

## Настройка параметров алгоритма сжатия: необязательно

Алгоритмы сжатия могут поддерживать определённые параметры, которые можно подстроить под конкретный набор данных. У ZRAM есть атрибут устройства algorithm_params, предоставляющий настройку параметров отдельно для каждого алгоритма.

Например, несколько алгоритмов сжатия поддерживают параметр level. Кроме того, некоторые алгоритмы сжатия поддерживают предварительно обученные словари (pre-trained dictionaries), которые значительно меняют характеристики алгоритмов. Чтобы настроить алгоритм сжатия на использование внешнего предварительно обученного словаря, передайте полный путь к словарю вместе с остальными параметрами:

```bash
#pass path to pre-trained zstd dictionary
echo "algo=zstd dict=/etc/dictionary" > /sys/block/zram0/algorithm_params

#pass path to pre-trained zstd dictionary and compression level
echo "algo=zstd level=8 dict=/etc/dictionary" > \
        /sys/block/zram0/algorithm_params

#same, but using algorithm priority
echo "algo=zstd priority=1" > /sys/block/zram0/recomp_algorithm
echo "priority=1 dict=/etc/dictionary" > \
        /sys/block/zram0/algorithm_params
```

Каждая запись в algorithm_params заменяет весь набор параметров соответствующего алгоритма; параметры, не указанные в записи, сбрасываются в значения по умолчанию. Настраивайте все параметры алгоритма одной записью:

```bash
#WRONG: the second write resets level back to its default value
echo "algo=zstd level=8" > /sys/block/zram0/algorithm_params
echo "algo=zstd dict=/etc/dictionary" > /sys/block/zram0/algorithm_params

#RIGHT
echo "algo=zstd level=8 dict=/etc/dictionary" > \
        /sys/block/zram0/algorithm_params
```

Выбирайте алгоритм сжатия до настройки его параметров. Параметры одного алгоритма не обязательно валидны для другого, поэтому смена алгоритма с определённым приоритетом сбрасывает параметры этого приоритета:

```bash
#WRONG: comp_algorithm write resets the previously configured level
echo "level=8" > /sys/block/zram0/algorithm_params
echo zstd > /sys/block/zram0/comp_algorithm

#RIGHT
echo zstd > /sys/block/zram0/comp_algorithm
echo "algo=zstd level=8" > /sys/block/zram0/algorithm_params
```

Параметры специфичны для алгоритма: не все алгоритмы поддерживают предварительно обученные словари, не все алгоритмы поддерживают level. Более того, для некоторых алгоритмов level управляет уровнем сжатия (чем выше значение, тем лучше степень сжатия; для некоторых алгоритмов оно может быть даже отрицательным), а для других алгоритмов level — это уровень ускорения (чем выше значение, тем ниже степень сжатия).

Параметры передаются алгоритму сжатия при инициализации устройства, поэтому о некорректных параметрах (или параметрах, которые выбранный алгоритм не поддерживает) сообщает запись в disksize, а не запись в algorithm_params, которой они были настроены.

## Установка размера диска

Установите размер диска, записав значение в узел sysfs ‘disksize’. Значение может быть как в байтах, так и с суффиксами памяти. Примеры:

```bash
# Initialize /dev/zram0 with 50MB disksize
echo $((50*1024*1024)) > /sys/block/zram0/disksize

# Using mem suffixes
echo 256K > /sys/block/zram0/disksize
echo 512M > /sys/block/zram0/disksize
echo 1G > /sys/block/zram0/disksize
```

Примечание: мало смысла создавать zram размером более чем в два раза больше объёма памяти, поскольку мы ожидаем степень сжатия 2:1. Учтите, что zram при неиспользовании занимает около 0,1% размера диска, поэтому огромный zram расточителен.

## Установка лимита памяти: необязательно

Установите лимит памяти, записав значение в узел sysfs ‘mem_limit’. Значение может быть как в байтах, так и с суффиксами памяти. Кроме того, значение можно менять на ходу. Примеры:

```bash
# limit /dev/zram0 with 50MB memory
echo $((50*1024*1024)) > /sys/block/zram0/mem_limit

# Using mem suffixes
echo 256K > /sys/block/zram0/mem_limit
echo 512M > /sys/block/zram0/mem_limit
echo 1G > /sys/block/zram0/mem_limit

# To disable memory limit
echo 0 > /sys/block/zram0/mem_limit
```

## Активация

```bash
mkswap /dev/zram0
swapon /dev/zram0

mkfs.ext4 /dev/zram1
mount /dev/zram1 /tmp
```

## Добавление/удаление устройств zram

zram предоставляет интерфейс управления, который позволяет динамически (по требованию) добавлять и удалять устройства.

Чтобы добавить новое устройство /dev/zramX, выполните операцию чтения атрибута hot_add. Он вернёт либо device id нового устройства (это значит, что можно использовать /dev/zram<id>), либо код ошибки.

Пример:

```text
cat /sys/class/zram-control/hot_add
1
```

Чтобы удалить существующее устройство /dev/zramX (где X — device id), выполните:

```bash
echo X > /sys/class/zram-control/hot_remove
```

## Статистика

Статистика по каждому устройству экспортируется в виде различных узлов под /sys/block/zram<id>/

Далее следует краткое описание экспортируемых атрибутов устройства. Подробнее читайте [ABI-файл testing/sysfs-block-zram](https://docs.kernel.org/admin-guide/abi-testing.html#abi-file-testing-sysfs-block-zram).

Имя | доступ | описание
---|---|---
disksize | RW | показать и установить размер диска устройства
initstate | RO | показывает состояние инициализации устройства
reset | WO | запускает сброс устройства
mem_used_max | WO | сбрасывает счётчик mem_used_max (см. далее)
mem_limit | WO | задаёт максимальный объём памяти, который ZRAM может использовать для хранения сжатых данных
writeback_limit | WO | задаёт максимальный объём записывающего ввода-вывода, который zram может выгрузить на бэкенд-устройство в единицах по 4 КБ
writeback_limit_enable | RW | показать и включить функцию writeback_limit
writeback_batch_size | RW | показать и установить максимальное число операций writeback «в полёте»
compressed_writeback | RW | показать и включить функцию сжатого writeback
comp_algorithm | RW | показать и сменить алгоритм сжатия
algorithm_params | WO | настроить параметры алгоритма сжатия
compact | WO | запускает компакцию памяти
debug_stat | RO | этот файл используется для целей отладки zram
backing_dev | RW | настроить бэкенд-хранилище, куда zram будет выгружать данные
idle | WO | пометить выделенный слот как неактивный (idle)

Пользовательскому пространству рекомендуется использовать следующие файлы для чтения статистики устройства.

Файл /sys/block/zram<id>/stat

Представляет статистику блочного слоя. Подробнее читайте [Block layer statistics in /sys/block/<dev>/stat](https://docs.kernel.org/block/stat.html).

Файл /sys/block/zram<id>/io_stat

Файл stat представляет статистику ввода-вывода устройства, не учитываемую блочным слоем и, следовательно, недоступную в файле zram<id>/stat. Он состоит из одной строки текста и содержит следующую статистику, разделённую пробелами:

> failed_reads | Количество неудачных чтений
> ---|---
> failed_writes | Количество неудачных записей
> invalid_io | Количество запросов ввода-вывода, не выровненных по размеру страницы
> notify_free | В зависимости от сценария использования устройства может учитывать
>
>   1. количество страниц, освобождённых из-за уведомлений об освобождении swap-слотов
>   2. количество страниц, освобождённых из-за запросов REQ_OP_DISCARD, отправленных через bio. Первые отправляются блочному swap-устройству при освобождении swap-слота, что подразумевает, что этот диск используется как swap-диск.
>
> Вторые отправляются файловой системой, смонтированной с опцией discard, всякий раз, когда какие-то блоки данных отбрасываются.

Файл /sys/block/zram<id>/mm_stat

Файл mm_stat представляет mm-статистику устройства. Он состоит из одной строки текста и содержит следующую статистику, разделённую пробелами:

> orig_data_size | несжатый размер данных, хранимых на этом диске. Единица: байты
> ---|---
> compr_data_size | сжатый размер данных, хранимых на этом диске
> mem_used_total | объём памяти, выделенный для этого диска. Включает фрагментацию аллокатора и накладные расходы метаданных, выделенные для этого диска. Так что пространственную эффективность аллокатора можно вычислить, используя compr_data_size и эту статистику. Единица: байты
> mem_limit | максимальный объём памяти, который ZRAM может использовать для хранения сжатых данных
> mem_used_max | максимальный объём памяти, потреблённый zram для хранения данных
> same_pages | количество записанных на этот диск страниц, заполненных одинаковым элементом. Для таких страниц память не выделяется.
> pages_compacted | количество страниц, освобождённых в ходе компакции
> huge_pages | количество несжимаемых страниц
> huge_pages_since | количество несжимаемых страниц с момента настройки zram

Файл /sys/block/zram<id>/bd_stat

Файл bd_stat представляет статистику бэкенд-устройства. Он состоит из одной строки текста и содержит следующую статистику, разделённую пробелами:

> bd_count | объём данных, записанных на бэкенд-устройство. Единица: 4К байт
> ---|---
> bd_reads | количество чтений с бэкенд-устройства. Единица: 4К байт
> bd_writes | количество записей на бэкенд-устройство. Единица: 4К байт

```bash
swapoff /dev/zram0

```

## Сброс

> Запишите любое положительное значение в узел sysfs ‘reset’:
>
> ```bash
> echo 1 > /sys/block/zram0/reset
> echo 1 > /sys/block/zram1/reset
> ```
>
> Это освобождает всю память, выделенную под данное устройство, и сбрасывает disksize в ноль. Перед повторным использованием устройства нужно снова установить disksize.

## Дополнительные возможности

### Отслеживание неактивных (IDLE) страниц

zram имеет встроенную поддержку отслеживания неактивных страниц (то есть выделенных, но не используемых). Эта возможность полезна, например, для writeback и пересжатия zram. Чтобы пометить страницы как неактивные, выполните следующую команду:

```bash
echo all > /sys/block/zramX/idle
```

Это пометит все выделенные страницы zram как неактивные. Пометка «неактивная» будет снята только при обращении к странице (блоку) (например, при перезаписи или освобождении). Кроме того, при включённом CONFIG_ZRAM_TRACK_ENTRY_ACTIME страницы можно помечать как неактивные по количеству секунд, прошедших с последнего обращения к конкретной странице zram:

```bash
echo 86400 > /sys/block/zramX/idle
```

В этом примере все страницы, к которым не обращались более 86400 секунд (одни сутки), будут помечены как неактивные.

### writeback

С CONFIG_ZRAM_WRITEBACK zram может выгружать неактивные/несжимаемые страницы на бэкенд-хранилище вместо хранения их в памяти. Чтобы использовать эту возможность, администратор должен настроить бэкенд-устройство с помощью:

```bash
echo /dev/sda5 > /sys/block/zramX/backing_dev
```

до установки disksize. На данный момент поддерживаются только разделы. Если администратор хочет использовать выгрузку несжимаемых страниц, это можно сделать так:

```bash
echo huge > /sys/block/zramX/writeback
```

Администратор может запросить выгрузку неактивных страниц в нужный момент так:

```bash
echo idle > /sys/block/zramX/writeback
```

С этой командой zram выгрузит неактивные страницы из памяти на хранилище.

Кроме того, если пользователь хочет выгружать только huge и неактивные страницы, это можно сделать так:

```bash
echo huge_idle > /sys/block/zramX/writeback
```

Если пользователь хочет выгружать только несжимаемые страницы (страницы, которые не может сжать ни один из алгоритмов), это можно сделать так:

```bash
echo incompressible > /sys/block/zramX/writeback
```

Если администратор хочет записать конкретную страницу устройства zram на бэкенд-устройство, можно записать индекс страницы в интерфейс:

```bash
echo "page_index=1251" > /sys/block/zramX/writeback
```

В Linux 6.16 этот интерфейс underwent некоторой переработке. Во-первых, интерфейс теперь поддерживает формат ключ=значение для всех своих параметров (type=huge_idle и т.д.). Во-вторых, была добавлена поддержка page_indexes, задающих диапазон (или диапазоны) страниц LOW-HIGH для выгрузки. Это сокращает число системных вызовов, но, что важнее, позволяет использовать оптимальную стратегию выбора целей пост-обработки. Пример использования:

```bash
echo "type=idle" > /sys/block/zramX/writeback
echo "page_indexes=1-100 page_indexes=200-300" > \
        /sys/block/zramX/writeback
```

Теперь мы также допускаем несколько параметров page_index на вызов и смесь одиночных страниц и диапазонов страниц:

```bash
echo page_index=42 page_index=99 page_indexes=100-200 \
        page_indexes=500-700 > /sys/block/zramX/writeback
```

Если на флеш-устройство идёт много записывающего ввода-вывода, потенциально возникает проблема износа флеш-памяти, поэтому администратор должен спроектировать ограничение записи, чтобы гарантировать здоровье хранилища на протяжении всего срока жизни продукта.

Для решения этой проблемы zram поддерживает возможность «writeback_limit». Значение по умолчанию «writeback_limit_enable» равно 0, так что никакая выгрузка не ограничивается. Иными словами, если администратор хочет применить бюджет выгрузки, он должен включить writeback_limit_enable так:

```bash
$ echo 1 > /sys/block/zramX/writeback_limit_enable
```

Как только writeback_limit_enable установлен, zram не разрешает никакую выгрузку, пока администратор не задаст бюджет через /sys/block/zramX/writeback_limit.

(Если администратор не включает writeback_limit_enable, значение writeback_limit, назначенное через /sys/block/zramX/writeback_limit, не имеет смысла.)

Если администратор хочет ограничить выгрузку до 400M в день, это можно сделать так:

```bash
$ MB_SHIFT=20
$ 4K_SHIFT=12
$ echo $((400<<MB_SHIFT>>4K_SHIFT)) > \
        /sys/block/zram0/writeback_limit.
$ echo 1 > /sys/block/zram0/writeback_limit_enable
```

Если администраторы хотят снова разрешить запись после исчерпания бюджета, это можно сделать так:

```bash
$ echo $((400<<MB_SHIFT>>4K_SHIFT)) > \
        /sys/block/zram0/writeback_limit
```

Если администратор хочет увидеть оставшийся бюджет выгрузки с момента последней установки:

```bash
$ cat /sys/block/zramX/writeback_limit
```

Если администратор хочет отключить лимит выгрузки:

```bash
$ echo 0 > /sys/block/zramX/writeback_limit_enable
```

Счётчик writeback_limit сбрасывается всякий раз при сбросе zram (например, перезагрузка системы, echo 1 > /sys/block/zramX/reset), так что отслеживать, сколько выгрузок произошло до сброса zram, чтобы выделить дополнительный бюджет выгрузки при следующей настройке, — задача пользователя.

По умолчанию zram хранит выгруженные страницы в распакованном (raw) виде, что означает, что операция writeback включает распаковку страницы перед записью на бэкенд-устройство. Это поведение можно изменить, включив возможность compressed_writeback, из-за которой zram записывает сжатые страницы на бэкенд-устройство, избегая накладных расходов на распаковку. Чтобы включить эту возможность, выполните:

```bash
$ echo yes > /sys/block/zramX/compressed_writeback
```

Обратите внимание, что эту возможность следует настраивать до инициализации устройства zramX.

В зависимости от типа хранилища бэкенд-устройства операция writeback может выигрывать от большего числа находящихся в полёте запросов записи (пакетная запись). Максимальное число операций writeback «в полёте» настраивается через атрибут writeback_batch_size. Чтобы изменить значение по умолчанию (32), выполните:

```bash
$ echo 64 > /sys/block/zramX/writeback_batch_size
```

Если администратор хочет измерить количество выгрузок за определённый период, это можно узнать по 3-му столбцу /sys/block/zram0/bd_stat.

### пересжатие (recompression)

С CONFIG_ZRAM_MULTI_COMP zram может пересжимать страницы с помощью альтернативных (вторичных) алгоритмов сжатия. Базовая идея в том, что альтернативный алгоритм сжатия может обеспечить лучшую степень сжатия ценой (потенциально) более медленных скоростей сжатия/распаковки. Альтернативный алгоритм сжатия может, например, успешнее сжимать huge-страницы (те, которые алгоритму по умолчанию сжать не удалось). Другое применение — пересжатие неактивных страниц: страницы, которые остыли и лежат в памяти, можно пересжать более эффективным алгоритмом и, следовательно, сократить использование памяти zsmalloc.

С CONFIG_ZRAM_MULTI_COMP zram поддерживает до 4 алгоритмов сжатия: один первичный и до 3 вторичных. Первичный компрессор zram описан в разделе «Выбор алгоритма сжатия», вторичные алгоритмы настраиваются через атрибут устройства recomp_algorithm.

Пример::

```text
#show supported recompression algorithms
cat /sys/block/zramX/recomp_algorithm
#1: lzo lzo-rle lz4 lz4hc [zstd]
#2: lzo lzo-rle lz4 [lz4hc] zstd
```

Альтернативные алгоритмы сжатия отсортированы по приоритету. В примере выше zstd используется как первый альтернативный алгоритм с приоритетом 1, а lz4hc настроен как алгоритм сжатия с приоритетом 2. Приоритет альтернативного алгоритма сжатия задаётся при конфигурации алгоритмов::

```bash
#select zstd recompression algorithm, priority 1
echo "algo=zstd priority=1" > /sys/block/zramX/recomp_algorithm
```

```bash
#select deflate recompression algorithm, priority 2
echo "algo=deflate priority=2" > /sys/block/zramX/recomp_algorithm
```

Ещё один атрибут устройства, который включает CONFIG_ZRAM_MULTI_COMP, — recompress, управляющий пересжатием.

Примеры::

```bash
#IDLE pages recompression is activated by `idle` mode
echo "type=idle priority=1" > /sys/block/zramX/recompress

#HUGE pages recompression is activated by `huge` mode
echo "type=huge priority=2" > /sys/block/zram0/recompress

#HUGE_IDLE pages recompression is activated by `huge_idle` mode
echo "type=huge_idle priority=1" > /sys/block/zramX/recompress
```

Количество неактивных страниц может быть значительным, поэтому пользовательское пространство может передать порог размера (в байтах) в knob recompress: zram пересожмёт только страницы равного или большего размера::

```bash
#recompress all pages larger than 3000 bytes
echo "threshold=3000 priority=1" > /sys/block/zramX/recompress

#recompress idle pages larger than 2000 bytes
echo "type=idle threshold=2000 priority=1" > \
        /sys/block/zramX/recompress
```

Также можно ограничить число страниц, которые пересжатие zram попытается пересжать::

```bash
echo "type=huge_idle priority=1 max_pages=42" > \
        /sys/block/zramX/recompress
```

Рекомендуется всегда указывать параметр priority. Хотя можно указать и параметр algo, чтобы zram определил приоритет по имени алгоритма, это не рекомендуется, поскольку может привести к неожиданным результатам, когда один и тот же алгоритм настроен с разными приоритетами (например, с разными параметрами). priority — единственный способ гарантировать, что будет использован ожидаемый алгоритм.

## Отслеживание памяти

С CONFIG_ZRAM_MEMORY_TRACKING пользователь может узнать информацию о блоке zram. Это может быть полезно для отлова холодных или несжимаемых страниц процесса с помощью *pagemap.

Если вы включите эту возможность, вы сможете видеть состояние блоков через /sys/kernel/debug/zram/zram0/block_state. Вывод выглядит так:

```text
300    75.033841 .wh...
301    63.806904 s.....
302    63.806919 ..hi..
303    62.801919 ....r.
304   146.781902 ..hi.n
```

Первый столбец

индекс блока zram.

Второй столбец

время доступа с момента загрузки системы

Третий столбец

состояние блока:

s:

одинаковая страница (same page)

w:

страница, записанная на бэкенд-хранилище

h:

huge-страница

i:

неактивная страница

r:

пересжатая страница (вторичным алгоритмом сжатия)

n:

ни один из алгоритмов (включая вторичные) не смог её сжать

Первая строка приведённого примера говорит, что к 300-му блоку обращались в 75.033841 сек, состояние блока — huge, поэтому он выгружен на бэкенд-хранилище. Это отладочная возможность, и не стоит полагаться на её корректную работу.
