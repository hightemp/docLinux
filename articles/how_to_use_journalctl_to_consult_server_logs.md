# Как использовать journalctl для просмотра логов сервера

Источник: [how_to_use_journalctl_to_consult_server_logs](https://alibaba-cloud.medium.com/how-to-use-journalctl-to-consult-server-logs-4b07311b0ab4)

Автор: Alexandru Andrei · Alibaba Cloud Tech Share · 16 октября 2018 · 9 мин чтения

_Tech Share_ — это программа стимулирования Alibaba Cloud, поощряющая обмен техническими знаниями и лучшими практиками в облачном сообществе.

Экземпляры Linux и другие *nix (Unix-подобные) операционные системы в целом (например, релизы BSD) поставляются с отличными предустановленными утилитами журналирования. Они перехватывают все важные загрузочные, ядерные, системные и программные сообщения, ошибки, предупреждения, уведомления и всё, что может быть полезно для мониторинга и отладки ПО, работающего на платформе. Традиционно этим занимались демоны `syslog`, `syslog-ng` и `rsyslog`. Каждая версия приносила постепенные улучшения, причём `rsyslog` — это демон логирования, который использовался большинством операционных систем на базе Linux в последние годы.

Поскольку большинство популярных дистрибутивов Linux перешли на systemd, идёт постоянный сдвиг к другому демону логирования — `systemd-journald`. В то время как `rsyslog` разделяет сообщения лога по разным файлам, таким как `/var/log/auth.log`, `/var/log/syslog` и так далее, `journald` централизует всё в одном месте. Он также использует двоичный формат вместо текстового формата для хранения данных. Это может дать некоторые преимущества. Например, становится проще увидеть, как различные события из нескольких областей системы связаны между собой, поскольку сообщения отсортированы по времени и отображаются в едином логе. Это может облегчить соединение точек и проследование цепочки ошибок, чтобы понять, где началась конкретная проблема. Фильтрация и сортировка сообщений, смена типа вывода и различные задачи также легче выполнять из-за способа, которым `systemd-journald` хранит данные. Ещё одна полезная особенность: утилита, используемая для отображения логов, автоматически форматирует текст, выделяя важные фрагменты информации жирным шрифтом или разными цветами; например, ошибки отображаются красным, что облегчает их замечание при прокрутке текста.

![Иллюстрация](/images/0bf24ab36e68f7c3b7677851261714a5.png)

Примечание: Шаги в этом руководстве были протестированы на Debian и Ubuntu. Хотя это крайне маловероятно, другие дистрибутивы могут потребовать адаптации представленных здесь команд. Это может произойти, если дистрибутив использует более старую версию systemd или определяет другие пути для конфигурационных файлов. Некоторые команды требуют прав администратора, поэтому вы должны быть вошли как пользователь root или добавлять к команде префикс `sudo`, если это необходимо.

## Включение постоянных логов

В большинстве дистрибутивов Linux `rsyslog` работает параллельно с демоном логирования systemd. Файлы логов `rsyslog` хранятся в каталоге `/var/log`. По этой причине вы обычно обнаружите, что `systemd-journald` хранит только энергозависимые (volatile) сообщения лога для текущей загрузки (логи хранятся в памяти, а не на диске). Чтобы включить постоянное журналирование, чтобы вы могли использовать `journalctl` для просмотра логов предыдущих загрузок, проверьте следующее:

```bash
grep Storage /etc/systemd/journald.conf
```

Если вывод — `Storage=auto` или `#Storage=auto`, это означает, что если каталог `/var/log/journal` существует, то journald будет хранить постоянные логи в этом месте. Если он не существует, логи будут храниться только в энергозависимой памяти, которая будет потеряна при перезагрузке или выключении экземпляра.

Проверьте, существует ли каталог:

```bash
ls /var/log/journal
```

Если он существует, вы можете пропустить его создание и перезапуск демона журнала. Если нет — создайте его, чтобы хранить логи на диске:

```bash
mkdir -p /var/log/journal
```

Затем перезапустите демона, чтобы применить изменения:

```bash
systemctl restart systemd-journald
```

Если `Storage` установлено в другое значение, такое как `volatile` или `none`, вы можете отредактировать конфигурационный файл и установить его в `persistent`:

```bash
sed -i '/Storage/ c\Storage=persistent' /etc/systemd/journald.conf
```

Команда выше ищет любую строку, содержащую строку “Storage”, и заменяет её на “Storage=persistent”.

Перезапустите журнал, чтобы применить изменения:

```bash
systemctl restart systemd-journald
```

Чтобы узнать больше о значениях, которые вы можете установить в `journald.conf`:

```bash
man journald.conf
```

Нажмите “q”, чтобы выйти из руководства.

Вы можете отредактировать конфигурационный файл с помощью:

```bash
nano /etc/systemd/journald.conf
```

Проверьте переменные, которые устанавливают ограничения на то, сколько архивов лога можно хранить в системе. Вот пример из операционной системы Debian 9:

```ini
#SystemMaxUse=
#SystemKeepFree=
#SystemMaxFileSize=
#SystemMaxFiles=100
```

Это ограничивает количество файлов лога, которое можно хранить, до 100. Вы также можете ограничить по дисковому пространству, если хотите. Чтобы отредактировать переменную, удалите предшествующий знак #. “#” сигнализирует, что строка закомментирована и не активна, но эти закомментированные строки показывают вам значения по умолчанию, которые используются, даже если они не заданы в этом файле. Чтобы изменить максимальное количество файлов журнала, которое следует хранить, вы отредактировали бы файл так:

```ini
#SystemMaxUse=
#SystemKeepFree=
#SystemMaxFileSize=
SystemMaxFiles=200
```

Затем вы нажали бы CTRL+X, затем “y”, затем ENTER, чтобы сохранить файл, и применили бы изменения с помощью:

```bash
systemctl restart systemd-journald
```

## Установка часового пояса

Сообщения лога предваряются датой и временем события. Но для большинства людей часовой пояс, используемый на экземпляре Alibaba Cloud ECS, не будет совпадать с часовым поясом, в котором в данный момент находится пользователь. Проверьте часовой пояс, установленный на экземпляре, с помощью:

```bash
timedatectl status
```

Чтобы увидеть доступные часовые пояса, вы можете применить:

```bash
timedatectl list-timezones
```

Вы можете нажимать PAGE UP и PAGE DOWN для навигации по этому списку. Нажмите “q”, чтобы выйти.

Команда для установки часового пояса — `timedatectl set-timezone Continent/City`. Имя континента и имя города должны начинаться с заглавных букв. Пример команды: `timedatectl set-timezone Europe/Amsterdam`. Теперь утилита `journalctl` будет показывать временные метки событий в вашем локальном времени.

## Фильтрация вывода журнала

Команда, которую вы используете для взаимодействия с файлами журнала, — `journalctl`. Чтобы иметь возможность читать системные журналы, вы должны быть либо вошли как пользователь root, либо добавлять к команде префикс `sudo`, если вы вошли как обычный пользователь с привилегиями sudo. Другой способ просматривать файлы системного лога из учётной записи обычного пользователя — добавить этого пользователя в группу `systemd-journal`. Вы можете сделать это командой вида `adduser name_of_user systemd-journal`. Затем выйдите из системы, если вы уже вошли как этот пользователь, и войдите снова. Теперь вы можете просматривать файлы журнала, не добавляя к команде префикс sudo и не вводя свой пароль.

Если вы выполните:

```bash
journalctl
```

Доступные файлы журнала будут объединены и показаны пользователю. Для отображения текста используется утилита `less`, а это значит, что вы можете использовать некоторые её горячие клавиши. Например, чтобы перейти к концу отображаемого текста, нажмите >. Чтобы вернуться к началу, нажмите <.

Вы можете искать текст от текущей отображаемой позиции и далее вниз, нажав /, введя текст, который вы хотите найти, например “ssh”, и затем нажав ENTER. Совпадающий текст будет выделен белым. Нажатие n будет искать следующее вхождение, а N — предыдущее. Чтобы искать вверх, а не вниз, нажмите ? и затем введите свой текст. Нажмите q, чтобы выйти из утилиты. Обратитесь к `man less` для получения дополнительной информации.

## Фильтрация по номеру загрузки

Каждый раз при загрузке вашей системы в журнале создаётся новая запись загрузки (boot). Вы можете увидеть все доступные с помощью:

```bash
journalctl --list-boots
```

Пример вывода:

```text
root@instance1:~# journalctl --list-boots
-4 b995cd57ae72431ba9be9560f28f80f7 Wed 2018-08-08 22:59:57 EEST—Wed 2018-08-08 23:00:04 EEST
-3 9b069b7c07a74e1a9d07d7ba830c22a8 Wed 2018-08-08 23:00:07 EEST—Wed 2018-08-08 23:32:35 EEST
-2 99439be7b99a4f67ad7b36768a508adc Wed 2018-08-08 23:32:39 EEST—Wed 2018-08-08 23:33:31 EEST
-1 0a261487baad44a394f86475ee5392f3 Wed 2018-08-08 23:33:35 EEST—Wed 2018-08-08 23:33:52 EEST
 0 6ee25c9b1cd94c7aaed4db674c14d431 Wed 2018-08-08 23:33:57 EEST—Wed 2018-08-08 23:49:17 EEST
```

Все они предваряются числом, начиная с 0, что означает текущую загрузку. “-1” означает одну загрузку назад, “-2” — две загрузки назад и так далее. Чтобы просмотреть сообщения из одной конкретной загрузки, вы можете использовать `journalctl -b 6ee25c9b1cd94c7aaed4db674c14d431`. Но это требует копипаста этой последовательности символов. Вы также можете выбрать загрузку по её индексному номеру:

```bash
journalctl -b -1
```

Нажмите “q”, чтобы выйти.

## Фильтрация по времени

Для фильтрации по времени событий вы можете использовать переключатели командной строки `-S` и `-U`. `-S` можно заменить на `--since`, а `-U` — на `--until`.

Вы можете использовать `year-month-day hour:minute:second` в качестве аргументов. Или вы можете использовать только часть даты или только часть времени. Вы также можете ввести `today` вместо `00:00`. `tomorrow` и `yesterday` также понимаются. И, вероятно, самый полезный тип аргументов времени — это относительные значения, такие как `-1h`, которые означают 1 час назад.

Чтобы увидеть сообщения с конца января 2018:

```bash
journalctl -S 2018-01-31
```

Чтобы увидеть сообщения, сгенерированные с полуночи:

```bash
journalctl -S 00:00
```

Эквивалентная команда:

```bash
journalctl -S today
```

Чтобы увидеть сообщения за последний час:

```bash
journalctl -S -1h
```

Такие команды обрезают содержимое с начала. Но вы можете захотеть обрезать с конца. Если вы не хотите видеть сообщения за последний час:

```bash
journalctl -U -1h
```

Эти фильтры можно комбинировать. Если вы хотите видеть только содержимое, сгенерированное вчера, удалив всё остальное:

```bash
journalctl -S yesterday -U 00:00
```

## Фильтрация по приоритету

Фильтрация по приоритету сообщений часто может быть полезна, особенно в случаях, когда вам нужно что-то отладить. Когда вы ищете то, что работает неправильно, обычные статусные сообщения бесполезны. Чтобы вывести только ошибки:

```bash
journalctl -p err
```

Чтобы вывести предупреждения:

```bash
journalctl -p warning
```

Другие типы уровней приоритета: alert, crit, debug, emerg, err, info, notice, warning. Они объясняются в руководстве по syslog, которое можно посмотреть с помощью `man 3 syslog`.

![Иллюстрация](/images/d52eaf775e1acb88c6aec07c123a0fa8.png)

Вы можете комбинировать разные типы фильтров вместе. Чтобы получить ошибки, сгенерированные за последний час:

```bash
journalctl -p err -S -1h
```

## Фильтрация по юниту, файлу или пути устройства

Иногда вы захотите видеть только логи, связанные с конкретной службой в вашей системе. Например, возможно, вы хотите видеть всё, что связано с демоном SSH:

```bash
journalctl -u ssh.service
```

Чтобы увидеть, какие службы генерируют сообщения лога, вы можете ввести в терминале `journalctl -u`, добавить пробел после `-u` и затем нажать TAB два раза.

Для фильтрации сообщений по пути к файлу работающего процесса:

```bash
journalctl /usr/sbin/sshd
```

Если вы хотите видеть сообщения лога, связанные с устройством, например с первым виртуальным диском в вашей системе:

```bash
journalctl /dev/vda
```

Чтобы показывать только логи, сгенерированные ядром Linux:

```bash
journalctl -k
```

## Управление выводом journalctl

По умолчанию журнал отображается, начиная с самой старой доступной записи. Но в большинстве случаев вы захотите видеть свежие записи первыми. Для этого вы можете использовать переключатель `-e` в команде вида `journalctl -b 0 -e`, чтобы перейти к концу журнала с последней загрузки. Это также ограничит вывод 1000 строками. Чтобы отобразить больше строк, вы можете использовать переключатель `-n`. Чтобы увидеть вывод с последней загрузки, перейти к его концу и ограничить количество строк до 10000:

```bash
journalctl -b 0 -e -n 10000
```

Иногда вы можете обнаружить, что пытаетесь воспроизвести ошибки или протестировать функциональность. Вместо того чтобы смотреть на то, что произошло в прошлом, в таких случаях вы захотите видеть вывод лога в реальном времени и затем взаимодействовать с программой, чтобы она генерировала события, которые вы можете видеть в реальном времени. Утилита journalctl имеет опцию «следования» (follow):

```bash
journalctl -f
```

Чтобы выйти из этого режима, нажмите CTRL+C.

Вывод journalctl также может быть обращён, чтобы сообщения отображались, начиная с самой новой записи и заканчивая самой старой:

```bash
journalctl -r
```

По умолчанию journalctl отображает текст, который легко читается людьми. Но иногда вам может понадобиться текст, который легко читается и обрабатывается другими программами. Например, вы можете захотеть интегрировать вывод в веб-приложение, и тогда вам может пригодиться JavaScript Object Notation (JSON):

```bash
journalctl -o json
```

Чтобы сделать его «pretty», то есть также легко читаемым людьми:

```bash
journalctl -o json-pretty
```

Чтобы увидеть все детали, которые демон логирования на самом деле имеет о каждом событии:

```bash
journalctl -o verbose
```

Сообщения лога также могут быть обогащены так называемым каталогом сообщений (Message Catalog). Для определённых событий, найденных в каталоге, это добавит объяснения, возможные решения, ссылки или любую другую дополнительную информацию, которая может быть полезна пользователю.

```bash
journalctl -x
```

## Управление дисковым пространством, используемым журналом

Чтобы увидеть, сколько места на диске занимают файлы журнала:

```bash
journalctl --disk-usage
```

Чтобы освободить место, у вас есть два варианта: либо удалять файлы на основе времени, либо удалять файлы на основе того, сколько места они используют. Следующие команды будут удалять только архивные файлы журнала. Активно используемые файлы журнала затронуты не будут. Чтобы удалить всё, что старше определённого времени:

```bash
journalctl --vacuum-time=3months
```

Вы также можете использовать “days”, “weeks” и “years”.

Для удаления на основе того, сколько дискового пространства используется:

```bash
journalctl --vacuum-size=2G
```

Это сохранит максимум 2 гигабайта архивных файлов журнала и удалит остальные. `M` может использоваться для мегабайт.

Чтобы узнать больше о journalctl, обратитесь к руководству с помощью `man journalctl`.
