# 1) NetworkManager

Как упоминалось в Части II, мы уже далеко отошли от стандартов POSIX и погрузились в специфичные для дистрибутивов Linux области управления разрешением DNS-имён.

В моём любимом дистрибутиве (Ubuntu) есть служба, которая доступна и часто устанавливается у меня как зависимость какого-нибудь другого пакета — [NetworkManager](https://en.wikipedia.org/wiki/NetworkManager). На самом деле это служба, разработанная RedHat в 2004 году, чтобы управлять сетевыми интерфейсами за вас.

Причём здесь DNS? Установите и выясните:

```bash
$ apt-get install -y network-manager
```

В моём дистрибутиве появляется конфигурационный файл.

```bash
$ cat /etc/NetworkManager/NetworkManager.conf
[main]
plugins=ifupdown,keyfile,ofono
dns=dnsmasq

[ifupdown]
managed=false
```

Видите там `dns=dnsmasq`? Это значит, что NetworkManager будет использовать `dnsmasq` для управления DNS на хосте.

* * *

# 2) dnsmasq

Программа dnsmasq — это уже знакомая нам вещь: очередной уровень косвенности для `/etc/resolv.conf`.

Технически dnsmasq умеет делать несколько вещей, но в первую очередь он выступает DNS-сервером, который может кэшировать запросы к другим DNS-серверам. Он работает на порту 53 (стандартный порт DNS) на всех локальных сетевых интерфейсах.

Так где же `dnsmasq` запущен? NetworkManager работает:

```bash
$ ps -ef | grep NetworkManager
root     15048     1  0 16:39 ?        00:00:00 /usr/sbin/NetworkManager --no-daemon
```

А вот процесса `dnsmasq` не существует:

```bash
$ ps -ef | grep dnsmasq
$
```

Хотя он настроен на использование, в вводящем в заблуждение порядке — на самом деле он даже не установлен! Так что установим его.

Но прежде чем устанавливать, проверим состояние `/etc/resolv.conf`.

```bash
$ cat /etc/resolv.conf
# Dynamic resolv.conf(5) file for glibc resolver(3) generated by resolvconf(8)
#     DO NOT EDIT THIS FILE BY HAND -- YOUR CHANGES WILL BE OVERWRITTEN
nameserver 10.0.2.2
search home
```

NetworkManager его не менял.

Если `dnsmasq` установлен:

```bash
$ apt-get install -y dnsmasq
```

То `dnsmasq` поднимается и работает:

```bash
$ ps -ef | grep dnsmasq
dnsmasq  15286     1  0 16:54 ?        00:00:00 /usr/sbin/dnsmasq -x /var/run/dnsmasq/dnsmasq.pid -u dnsmasq -r /var/run/dnsmasq/resolv.conf -7 /etc/dnsmasq.d,.dpkg-dist,.dpkg-old,.dpkg-new --local-service --trust-anchor=.,19036,8,2,49AAC11D7B6F6446702E54A1607371607A1A41855200FD2CE1CDDE32F24E8FB5
```

И `/etc/resolv.conf` снова изменился!

```text
root@linuxdns1:~# cat /etc/resolv.conf
# Dynamic resolv.conf(5) file for glibc resolver(3) generated by resolvconf(8)
#     DO NOT EDIT THIS FILE BY HAND -- YOUR CHANGES WILL BE OVERWRITTEN
nameserver 127.0.0.1
search home
```

А `netstat` показывает, что `dnsmasq` обслуживает порт 53 на всех интерфейсах:

```text
$ netstat -nlp4
Active Internet connections (only servers)
Proto Recv-Q Send-Q Local Address     Foreign Address State   PID/Program name
tcp        0      0 127.0.0.1:53      0.0.0.0:*       LISTEN  15286/dnsmasq 
tcp        0      0 10.0.2.15:53      0.0.0.0:*       LISTEN  15286/dnsmasq
tcp        0      0 172.28.128.11:53  0.0.0.0:*       LISTEN  15286/dnsmasq
tcp        0      0 0.0.0.0:22        0.0.0.0:*       LISTEN  1237/sshd
udp        0      0 127.0.0.1:53      0.0.0.0:*                  15286/dnsmasq
udp        0      0 10.0.2.15:53      0.0.0.0:*                  15286/dnsmasq   
udp        0      0 172.28.128.11:53  0.0.0.0:*                  15286/dnsmasq   
udp        0      0 0.0.0.0:68        0.0.0.0:*                  10758/dhclient
udp        0      0 0.0.0.0:68        0.0.0.0:*                  10530/dhclient
udp        0      0 0.0.0.0:68        0.0.0.0:*                  10185/dhclient
```

# 3) Разбор dnsmasq

Теперь мы в ситуации, когда все DNS-запросы уходят на `127.0.0.1:53`, — и что происходит дальше?

Подсказку можно получить, ещё раз взглянув на папку `/var/run`. `resolv.conf` в `resolvconf` изменился и теперь указывает туда, где обслуживается `dnsmasq`:

```bash
$ cat /var/run/resolvconf/resolv.conf
# Dynamic resolv.conf(5) file for glibc resolver(3) generated by resolvconf(8)
#     DO NOT EDIT THIS FILE BY HAND -- YOUR CHANGES WILL BE OVERWRITTEN
nameserver 127.0.0.1
search home
```

тогда как появилась новая папка `dnsmasq` со своим `resolv.conf`.

```bash
$ cat /run/dnsmasq/resolv.conf
nameserver 10.0.2.2
```

в котором находится nameserver, выданный нам по `DHCP`.

Мы можем рассуждать об этом, не слишком углубляясь, но что, если мы действительно хотим знать, что происходит?

# 4) Отладка dnsmasq

Часто я ловил себя на том, что мне интересно, каково состояние dnsmasq. К счастью, из него можно вытащить прилично информации, если изменить эту строку в `/etc/dnsmasq.conf`:

```text
#log-queries
```

на:

```text
log-queries
```

и перезапустить `dnsmasq`.

Теперь, если выполнить простое:

```bash
$ ping -c1 bbc.co.uk
```

вы увидите в `/var/log/syslog` что-то вроде этого (`[...]` означает, что начало строки совпадает с предыдущей):

```text
Jul  3 19:56:07 ubuntu-xenial dnsmasq[15372]: query[A] bbc.co.uk from 127.0.0.1
[...] forwarded bbc.co.uk to 10.0.2.2
[...] reply bbc.co.uk is 151.101.192.81
[...] reply bbc.co.uk is 151.101.0.81
[...] reply bbc.co.uk is 151.101.64.81
[...] reply bbc.co.uk is 151.101.128.81
[...] query[PTR] 81.192.101.151.in-addr.arpa from 127.0.0.1
[...] forwarded 81.192.101.151.in-addr.arpa to 10.0.2.2
[...] reply 151.101.192.81 is NXDOMAIN
```

это показывает, что получил `dnsmasq`, куда был перенаправлен запрос и какой ответ пришёл.

Если запрос возвращается из кэша (или, точнее, локальное «время жизни» (time-to-live) для запроса ещё не истекло), в логах это выглядит так:

```text
[...] query[A] bbc.co.uk from 127.0.0.1
[...] cached bbc.co.uk is 151.101.64.81
[...] cached bbc.co.uk is 151.101.128.81
[...] cached bbc.co.uk is 151.101.192.81
[...] cached bbc.co.uk is 151.101.0.81
[...] query[PTR] 81.64.101.151.in-addr.arpa from 127.0.0.1
```

а если вам когда-нибудь захочется узнать, что лежит в кэше, вы можете побудить dnsmasq отправить его в тот же лог-файл, послав сигнал `USR1` процессу dnsmasq по его идентификатору:

```bash
$ kill -SIGUSR1 <(cat /run/dnsmasq/dnsmasq.pid)
```

и вывод дампа выглядит так:

```text
Jul  3 15:08:08 ubuntu-xenial dnsmasq[15697]: time 1530630488
[...] cache size 150, 0/5 cache insertions re-used unexpired cache entries.
[...] queries forwarded 2, queries answered locally 0
[...] queries for authoritative zones 0
[...] server 10.0.2.2#53: queries sent 2, retried or failed 0
[...] Host             Address          Flags      Expires
```

#### Альтернативы dnsmasq

`dnsmasq` — не единственный вариант, который можно передать в параметр dns в NetworkManager. Есть `none`, который ничего не делает с `/etc/resolv.conf`, `default`, который, как утверждается, «обновляет `resolv.conf`, отражая активные на данный момент соединения», и `unbound`, который взаимодействует со службой `unbound`, а также `dnssec-triggerd`, который занимается безопасностью DNS и здесь не рассматривается.
