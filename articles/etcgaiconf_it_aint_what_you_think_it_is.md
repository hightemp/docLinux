# /etc/gai.conf — это совсем не то, что вы думаете

Источник: [/etc/gai.conf - it ain't what you think it is](http://biplane.com.au/blog/?p=122)

Карл Ауэр (kauer) · рубрика IPv6 Technical

Если вы прочитаете документацию (например, «man gai.conf»), вас можно простить за то, что вы решили, будто содержимое /etc/gai.conf управляет выбором адреса источника и назначения в IPv6. Вы ошиблись бы.

Этот файл действительно управляет выбором адреса назначения; при выборе же адреса источника он полностью игнорируется. Дисклеймер: я говорю здесь про Ubuntu, но подозреваю, что все производные Debian, а вероятно, и все Linux имеют ту же проблему.

В /etc/gai.conf содержится три типа информации: таблица меток (label), таблица приоритетов (precedence) и таблица областей (scope) IPv4. Информация о метках нужна при выборе адреса источника; все три типа информации нужны при выборе адреса назначения.

Для выбора адреса _назначения_ /etc/gai.conf работает так, как заявлено. Если вы измените /etc/gai.conf, новая информация сразу начнёт использоваться всеми новыми процессами. Запущенным процессам потребуется перезапуск, прежде чем они «увидят» изменение. Вы можете поместить в файл «reload yes», чтобы даже запущенные процессы немедленно реагировали на изменения, но это приведёт к тому, что все процессы при каждом DNS-запросе будут проверять время последнего изменения /etc/gai.conf (а в худшем случае и перечитывать его), что, вероятно, плохая идея. Комментарии в /etc/gai.conf тоже не советуют так делать.

Однако при выборе _исходного_ адреса /etc/gai.conf игнорируется. Значит, нужно найти другой способ, чтобы информация о метках всё же использовалась.

Самый очевидный путь — просто воспользоваться программой ip и вставлять её по мере необходимости:

```bash
   ip addrlabel add prefix 2001:db8:0:100::/64 label 25
```

Но это пришлось бы делать при каждом запуске системы, для целого набора префиксов — и где хранилась бы эта информация?

Мне нравится идея держать всю информацию о выборе адресов в одном месте. Поскольку выбор адреса назначения уже управляется через /etc/gai.conf, а таблица меток, по идее, должна быть одной и той же для выбора адресов назначения и источника, логично использовать файл /etc/gai.conf и для управления выбором исходного адреса — как, судя по всему, и задумывали его создатели. Поэтому мы, бессмертными словами Жан-Люка Пикара, «сделаем это» (make it so) с помощью подходящего скрипта.

Пока /etc/gai.conf существует и пока в нём есть хотя бы одна строка, начинающаяся с «label», приведённый ниже скрипт заменит всю существующую информацию о выборе исходного адреса информацией из /etc/gai.conf. Это же поведение описано в самом /etc/gai.conf и его man-странице.

Простого способа реализовать автоматическую «перезагрузку» (reload) нет. Для выбора адреса назначения существует естественная и простая посервисная синхронизация через вызовы getaddrinfo(), которые выполняет каждый процесс. Для выбора исходного адреса естественной точки синхронизации нет. Перезагрузка должна сначала удалить всю информацию о выборе адреса назначения (примечание переводчика: в оригинале, судя по контексту, имеется в виду информация о выборе исходного адреса), затем заменить её, причём замена не атомарна. Если это произойдёт ровно в тот момент, когда какой-то процесс пытается установить сетевое соединение, результат может быть далёк от оптимального.

Поэтому скрипт лучше всего запускать при старте системы вместе с другими сетевыми стартовыми скриптами. Впрочем, его можно запускать и вручную, когда потребуется. Скрипт должен запускаться от имени root.

Сохраните скрипт как /etc/init.d/ipv6_sas. Настройте стартовые ссылки SysV, чтобы он запускался на уровнях выполнения 2, 3, 4 и 5 и останавливался на уровнях 0, 1 и 6. Либо добавьте подходящий conf-файл в /etc/init (см. ниже) и позвольте Upstart сделать всю работу.

```bash
#!/bin/sh

GAICONF=/etc/gai.conf
PREFIX=$1
LABEL=$2

# This case statement allows this script to be used as a SysV
# startup script. Delete it if you will only be running the
# script manually or via Upstart.
case "$1" in
  start)
    $0
        exit $?
    ;;
  restart|reload|force-reload)
    $0
        exit $?
    ;;
  stop)
    # No-op
        exit 0
    ;;
esac

if [ -z $PREFIX ] ; then
   if [ -r $GAICONF ] ; then
      # Is there at least one "label" line?
      grep "^\s*label" /etc/gai.conf > /dev/null
      RETCODE=$?
      if [ $RETCODE = 0 ] ; then
         echo "flushing existing source address selection info..."
         ip addrlabel flush
         echo "adding source address selection info from $GAICONF..."
         grep "^\s*label" /etc/gai.conf | cut -d\  -f2- | xargs -n2 $0
         echo "...done."
      else
         echo "$GAICONF contains no \"label\" lines. No changes made."
      fi
   else
      echo "$GAICONF not found or not readable. No changes made."
   fi
   exit 0
else
   echo "\tadding prefix $PREFIX with label $LABEL"
   ip addrlabel add prefix $PREFIX label $LABEL
fi
```

Чтобы запускать этот скрипт через Upstart, поместите следующие строки в файл с именем /etc/init/ipv6_sas.conf:

```text
description     "Read IPv6 source address selection rules"
author          "Karl Auer <kauer@biplane.com.au>"

start on (net-device-up
          and local-filesystems
          and runlevel [2345])
stop on runlevel [016]
respawn
env HOME=/
umask 007
exec /etc/init.d/ipv6_sas
```
