## ОПИСАНИЕ

Системный вызов **dup**() выделяет новый файловый дескриптор, который ссылается на то же открытое файловое описание (open file description), что и дескриптор _oldfd_. (Объяснение открытых файловых описаний см. в [open(2)](../man2/open.2.html).) Гарантируется, что номер нового файлового дескриптора — это наименьший номер файлового дескриптора, который не использовался в вызывающем процессе.

После успешного возврата старый и новый файловые дескрипторы можно использовать взаимозаменяемо. Поскольку оба файловых дескриптора ссылаются на одно и то же открытое файловое описание, они совместно используют смещение в файле (file offset) и флаги состояния файла (file status flags); например, если смещение в файле изменено с помощью [lseek(2)](../man2/lseek.2.html) для одного из файловых дескрипторов, то смещение изменится и для другого файлового дескриптора.

Два файловых дескриптора не используют совместно флаги файлового дескриптора (флаг close-on-exec — закрыть при exec). Флаг close-on-exec (**FD_CLOEXEC**; см. [fcntl(2)](../man2/fcntl.2.html)) для дублирующего дескриптора выключен.

**dup2()**

Системный вызов **dup2**() выполняет ту же задачу, что и **dup**(), но вместо использования наименьшего неиспользованного номера файлового дескриптора он использует номер файлового дескриптора, указанный в _newfd_. Другими словами, файловый дескриптор _newfd_ настраивается так, что теперь он ссылается на то же открытое файлое описание, что и _oldfd_.

Если файловый дескриптор _newfd_ ранее был открыт, он закрывается перед повторным использованием; закрытие выполняется тихо (т. е. любые ошибки во время закрытия не сообщаются **dup2**()).

Шаги закрытия и повторного использования файлового дескриптора _newfd_ выполняются _атомарно_. Это важно, поскольку попытка реализовать эквивалентную функциональность с помощью [close(2)](../man2/close.2.html) и **dup**() была бы подвержена состояниям гонки (race condition), при которых _newfd_ мог бы быть повторно использован между этими двумя шагами. Такое повторное использование могло бы произойти из-за того, что основная программа прерывается обработчиком сигнала, выделяющим файловый дескриптор, или из-за того, что параллельный поток выделяет файловый дескриптор.

Обратите внимание на следующие моменты:

•  Если _oldfd_ не является допустимым файловым дескриптором, вызов завершается ошибкой, и _newfd_ не закрывается.

•  Если _oldfd_ является допустимым файловым дескриптором, а _newfd_ имеет то же значение, что и _oldfd_, то **dup2**() ничего не делает и возвращает _newfd_.

**dup3()**

**dup3**() аналогичен **dup2**(), за исключением того, что:

•  Вызывающий может принудительно установить флаг close-on-exec для нового файлового дескриптора, указав **O_CLOEXEC** в _flags_. Причины, почему это может быть полезно, см. в описании того же флага в [open(2)](../man2/open.2.html).

•  Если _oldfd_ равен _newfd_, то **dup3**() завершается с ошибкой **EINVAL**.

## ВОЗВРАЩАЕМОЕ ЗНАЧЕНИЕ

При успешном выполнении эти системные вызовы возвращают новый файловый дескриптор. При ошибке возвращается -1, а _[errno](../man3/errno.3.html)_ устанавливается для индикации ошибки.

## ОШИБКИ

```text
       **EBADF** _oldfd_ не является открытым файловым дескриптором.

       **EBADF** _newfd_ выходит за пределы допустимого диапазона файловых
              дескрипторов (см. обсуждение **RLIMIT_NOFILE** в [getrlimit(2)](../man2/getrlimit.2.html)).

       **EBUSY** (только Linux) Может быть возвращён **dup2**() или **dup3**()
              во время состояния гонки с [open(2)](../man2/open.2.html) и **dup**().

       **EINTR** Вызов **dup2**() или **dup3**() был прерван сигналом; см.
              [signal(7)](../man7/signal.7.html).

       **EINVAL** (**dup3**()) _flags_ содержат недопустимое значение.

       **EINVAL** (**dup3**()) _oldfd_ был равен _newfd_.

       **EMFILE** Достигнут предел на количество открытых файловых
              дескрипторов для процесса (см. обсуждение **RLIMIT_NOFILE**
              в [getrlimit(2)](../man2/getrlimit.2.html)).

       **ENOMEM** Недостаточно памяти ядра.
```

## ЗАМЕЧАНИЯ

Ошибка, возвращаемая **dup2**(), отличается от ошибки, возвращаемой **fcntl(**..., **F_DUPFD**, ...**)**, когда _newfd_ выходит за пределы диапазона. В некоторых системах **dup2**() также иногда возвращает **EINVAL**, как **F_DUPFD**.

Если _newfd_ был открыт, любые ошибки, которые могли бы быть сообщены во время [close(2)](../man2/close.2.html), теряются. Если это важно, то — если только программа не является однопоточной и не выделяет файловые дескрипторы в обработчиках сигналов — правильный подход состоит _не_ в том, чтобы закрыть _newfd_ перед вызовом **dup2**(), из-за состояния гонки, описанного выше. Вместо этого можно использовать код наподобие следующего:

```c
           /* Получить дубликат 'newfd', который впоследствии можно
              использовать для проверки ошибок close(); ошибка EBADF
              означает, что 'newfd' не был открыт.  */
```

```c
           tmpfd = dup(newfd);
           if (tmpfd == -1 && errno != EBADF) {
               /* Обработать неожиданную ошибку dup().  */
           }
```

```c
           /* Атомарно продублировать 'oldfd' на 'newfd'.  */
```

```c
           if (dup2(oldfd, newfd) == -1) {
               /* Обработать ошибку dup2().  */
           }
```

```c
           /* Теперь проверить ошибки close() для файла, на который
              изначально ссылался 'newfd'.  */
```

```c
           if (tmpfd != -1) {
               if (close(tmpfd) == -1) {
                   /* Обработать ошибки от close.  */
               }
           }
```
