# Настройка аудита системы Linux с помощью auditd

Источник: [Configure Linux system auditing with auditd](https://www.redhat.com/en/blog/configure-linux-auditing-auditd)

Ashish Bharadwaj Madabhushana · 26 октября 2021 · 3 мин

Системные администраторы используют аудит для обнаружения нарушений безопасности и отслеживания связанной с безопасностью информации на своих системах. На основе предварительно настроенных правил и свойств **демон аудита** (`auditd`) создаёт записи журнала, фиксирующие информацию о событиях, происходящих в системе. Администраторы используют эту информацию, чтобы проанализировать, что пошло не так с политиками безопасности, и улучшить их, приняв дополнительные меры.

Эта статья посвящена установке, настройке и управлению службой аудита. В ней также показано, как определять правила аудита, выполнять поиск по журналам аудита и создавать отчёты аудита. Если вы новичок в аудите системы, статья поможет вам получить базовое понимание и навыки использования аудита в вашей системе.

## Установка пакетов аудита

Пакет `audit` по умолчанию установлен в Red Hat Enterprise Linux (RHEL) 7 и новее. Если он не установлен, добавьте его следующей командой:

```bash
$ sudo dnf install audit
```

Файл конфигурации аудита находится по пути `/etc/audit/auditd.conf`. Он содержит стандартные параметры конфигурации, изменяющие поведение демона `auditd`.

## Управление службой аудита

Когда `auditd` настроен, запустите службу для сбора информации аудита:

```bash
$ sudo service auditd start
```

Единственная причина использовать команду `service` вместо `systemctl` — корректная запись значения идентификатора пользователя (UID).

Включите демон `auditd`, чтобы он запускался при загрузке системы:

```bash
$ sudo systemctl enable auditd
```

## Определение правил аудита

С помощью инструмента `auditctl` вы можете добавлять правила аудита для любого нужного вам системного вызова.

Порядок правил важен для их корректной работы: служба действует по принципу «первое совпавшее правило побеждает» (first-match-win).

Следующий шаг — определение **правила наблюдения** (watch rule). Это правило отслеживает, был ли доступ к файлу или каталогу определённых типов, включая чтение, запись, выполнение и изменение атрибутов.

Синтаксис определения правил наблюдения:

```text
auditctl -w path_to_file -p permissions -k key_name
```

Чтобы аудитить действия по созданию пользователей, сначала добавьте наблюдение за файлом `/etc/passwd` для отслеживания доступа на запись и изменение атрибутов и добавьте пользовательский ключ для журналирования всех сообщений (этот пользовательский ключ удобно использовать для фильтрации сообщений журнала):

```bash
$ sudo auditctl -w /etc/passwd -p wa -k user-modify
```

Затем добавьте нового пользователя. Это изменит файл `/etc/passwd`:

```bash
$ sudo useradd testuser
```

Наконец, проверьте, зафиксировал ли `auditd` это изменение. По умолчанию `auditd` хранит журналы в файле `/var/log/audit/audit.log`:

```bash
$ sudo cat /var/log/audit/audit.log | grep user-modify
```

В выводе отображаются различные свойства: какой системный вызов и каким пользователем был инициирован, тип изменения, UID и идентификатор группы (GID) пользователя, выполнившего команду, и многое другое.

Загляните в man-страницу `auditctl`, чтобы увидеть больше примеров аудита. Для просмотра конкретных опций используйте `auditctl --help`.

## Определение постоянных правил аудита

Чтобы правила аудита сохранялись после перезагрузок, добавьте их в файл `/etc/audit/rules.d/audit.rules`. Этот файл содержит команды `auditctl` в том виде, в каком они вводились бы в командной строке, но без самой команды `auditctl` в начале.

Определите в файле `audit.rules` постоянные правила для наблюдения за изменениями файла `/etc/passwd`.

Откройте файл `/etc/audit/rules.d/audit.rules` в своём любимом текстовом редакторе и добавьте строку:

```text
-w /etc/passwd -p wa -k user-modify
```

Сохраните файл, затем перезагрузите демона `auditd`, чтобы применить изменения из конфигурации в файле правил:

```bash
$ sudo service auditd reload
```

Выполните `auditctl -l`, чтобы вывести список правил.

Наконец, добавьте нового пользователя или измените любые параметры, вызывающие изменение файла `/etc/passwd`. Изменение будет зафиксировано в `/var/log/audit/audit.log`, и даже после перезагрузки системы правила сохранятся.

## Поиск по журналам аудита

Для поиска по журналам аудита используйте инструмент `ausearch`. По умолчанию он выполняет поиск в файле `/var/log/audit/audit.log`.

Например, чтобы найти записи журнала по **key_name**:

```bash
$ sudo ausearch -i -k user-modify
```

## Создание отчётов аудита

Для запросов и создания отчётов аудита на основе журналов аудита используйте инструмент `aureport`.

Например, чтобы сгенерировать отчёт по всем событиям исполнения, выполните:

```bash
$ sudo aureport -x
```

## Заключение

В этой статье вы узнали, что такое `auditd`, установили пакеты, необходимые для `auditd`, и управляли службой `auditd`, запуская, включая и перезапуская её там и тогда, где и когда это нужно. Вы научились определять правила `auditd` временно с помощью `auditctl` и постоянно — в файле `audit.rules`. Наконец, вы выполняли поиск по журналам аудита и создавали отчёты аудита командами `ausearch` и `aureport` соответственно.
