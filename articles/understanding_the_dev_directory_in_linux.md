# Каталог /dev в Linux

Источник: [Understanding the /dev Directory in Linux](https://www.baeldung.com/linux/dev-directory)

baeldung · обновлено 18 марта 2024

Linux и Unix-подобные операционные системы следуют стандарту иерархии файловой системы (Filesystem Hierarchy Standard, FHS). FHS определяет структуру файловой системы. Другими словами, он определяет основные каталоги и их содержимое. Один из важнейших каталогов системы — каталог _/dev/_. В этом руководстве мы глубже разберём каталог _/dev/_ и его функции.

## 2. Какова функция каталога /dev?

Каталог _/dev/_ состоит из файлов, которые представляют устройства, подключённые к локальной системе. Однако это не обычные файлы, в которые пользователь может читать и писать; такие файлы называются файлами устройств или специальными файлами:

```text
[root@localhost dev]# ls -l
total 0
crw-r--r--. 1 root root     10, 235 Sep 29 12:08 autofs
drwxr-xr-x. 3 root root          60 Sep 29 12:07 bus
lrwxrwxrwx. 1 root root           3 Sep 29 12:10 cdrom -> sr0
drwxr-xr-x. 2 root root         3100 Sep 29 12:10 char
crw-------. 1 root root      5,   1 Sep 29 12:08 console
lrwxrwxrwx. 1 root root          11 Sep 29 12:07 core -> /proc/kcore
drwxr-xr-x. 3 root root          60 Sep 29 12:07 cpu
crw-------. 1 root root     10,  62 Sep 29 12:08 cpu_dma_latency
drwxr-xr-x. 7 root root         140 Sep 29 12:08 disk
brw-rw----. 1 root disk    253,   0 Sep 29 12:08 dm-0
...
```

**Файлы устройств — это абстракции стандартных устройств, с которыми приложения взаимодействуют через системные вызовы ввода-вывода (I/O).** Файлы устройств, соответствующие аппаратным устройствам, делятся на две основные категории: специальные символьные файлы и специальные блочные файлы.

## 3. В чём разница между специальными символьными и блочными файлами?

Специальные символьные файлы — это простые интерфейсы к символьным устройствам. Аналогично, специальные блочные файлы — это простые интерфейсы к блочным устройствам. Разница между этими устройствами зависит от того, как операционная система читает с них данные. **Драйвер взаимодействует с символьным устройством, отправляя отдельные символы в качестве данных, например байты.** Кроме того, символьным устройствам не требуется буферизация при взаимодействии с драйвером. С другой стороны, драйвер обращается к данным блочных устройств через кэш. Более того, **драйвер взаимодействует с блочным устройством, отправляя целый блок данных**. Например, символьными устройствами являются звуковые карты или последовательные порты, тогда как блочными устройствами являются жёсткие диски или USB-накопители. Мы определяем блочные и символьные устройства по букве, стоящей перед правами доступа. Буква _'b'_, отображаемая в первом столбце, обозначает блочное устройство. С другой стороны, буква 'c' в первом столбце символизирует символьное устройство:

```text
[root@localhost dev]# ls -l
total 0
crw-r--r--. 1 root root     10, 235 Sep 16 11:52 autofs
drwxr-xr-x. 2 root root         280 Sep 16 11:52 block
drwxr-xr-x. 2 root root          60 Sep 16 11:52 bsg
drwxr-xr-x. 3 root root          60 Sep 16 11:52 bus
lrwxrwxrwx. 1 root root           3 Sep 16 13:05 cdrom -> sr0
drwxr-xr-x. 2 root root         3100 Sep 16 13:05 char
crw-------. 1 root root      5,   1 Sep 16 11:52 console
lrwxrwxrwx. 1 root root          11 Sep 16 11:52 core -> /proc/kcore
drwxr-xr-x. 3 root root          60 Sep 16 11:52 cpu
crw-------. 1 root root     10,  62 Sep 16 11:52 cpu_dma_latency
drwxr-xr-x. 7 root root         140 Sep 16 11:52 disk
brw-rw----. 1 root disk    253,   0 Sep 16 11:52 dm-0
brw-rw----. 1 root disk    253,   1 Sep 16 11:52 dm-1
brw-rw----. 1 root disk    253,   2 Sep 16 11:52 dm-2
```

Большинство устройств, которые мы видим, — это символьные или блочные устройства. Однако существуют и другие типы устройств, например устройства сокетов и пайпов (pipe).

## 4. Что такое псевдоустройства?

Псевдоустройства (pseudo-device) не соответствуют аппаратным устройствам. Иными словами, они предоставляют ряд полезных функций. Например, _/dev/random_ — это функция, генерирующая случайные данные. Псевдоустройства также являются символьными устройствами. Отличить псевдоустройства от других символьных устройств можно по старшему номеру устройства. Более того, **драйверы устройств связываются с устройством через уникальное значение, называемое старшим номером (major number)**. Старший и младший номера отображаются при выполнении команды [_ls -l_](https://www.gnu.org/software/coreutils/ls). Два числа разделены запятой. Сначала идёт старший номер, затем младший. В нашем случае драйвер, связанный с псевдоустройствами, — это драйвер 1, поскольку наш старший номер — 1:

```text
[root@localhost dev]# ls -l |grep random
crw-rw-rw-. 1 root root      1,   8 Sep 29 12:08 random
```

Мы также можем посмотреть старший и младший номера, выполнив [_stat_](https://www.gnu.org/software/coreutils/stat). Эти числа отображаются в поле device type:

```text
[root@localhost dev]# stat /dev/random
  File: /dev/random
  Size: 0         	Blocks: 0          IO Block: 4096   character special file
Device: 6h/6d	Inode: 10216       Links: 1     Device type: 1,8
Access: (0666/crw-rw-rw-)  Uid: (    0/    root)   Gid: (    0/    root)
Context: system_u:object_r:random_device_t:s0
Access: 2021-09-16 11:52:35.644848848 -0400
Modify: 2021-09-16 11:52:35.644848848 -0400
Change: 2021-09-16 11:52:35.644848848 -0400
 Birth: -
```

## 5. Почему здесь так много символических ссылок?

Некоторые файлы устройств в каталоге _/dev/_ отображаются не как блочные или символьные устройства. Вместо этого там перечислены символические ссылки:

```text
[root@localhost dev]# ls -lhaF| grep ^l
lrwxrwxrwx.  1 root root           3 Sep 17 09:07 cdrom -> sr0
lrwxrwxrwx.  1 root root          11 Sep 17 09:06 core -> /proc/kcore
lrwxrwxrwx.  1 root root          13 Sep 17 09:06 fd -> /proc/self/fd/
lrwxrwxrwx.  1 root root          12 Sep 17 09:06 initctl -> /run/initctl|
lrwxrwxrwx.  1 root root          28 Sep 17 09:06 log -> /run/systemd/journal/dev-log=
lrwxrwxrwx.  1 root root           4 Sep 17 09:06 rtc -> rtc0
lrwxrwxrwx.  1 root root          15 Sep 17 09:06 stderr -> /proc/self/fd/2
lrwxrwxrwx.  1 root root          15 Sep 17 09:06 stdin -> /proc/self/fd/0
lrwxrwxrwx.  1 root root          15 Sep 17 09:06 stdout -> /proc/self/fd/1|
```

Символические ссылки в каталоге _/dev_ существуют по многим причинам. Например, глядя на _/dev/stdin_, мы видим, что он указывает на _/proc/self/fd/0_. Это потому, что каталог /proc/self находится в файловой системе /_proc_. Когда процесс читает _/proc/self_, он получает информацию о себе, используя свой идентификатор процесса. Так что каталог _/proc/self_ тоже является символической ссылкой:

```text
[root@localhost dev]# ls -l /proc/self/fd/0
lrwx------. 1 root root 64 Sep 17 12:02 /proc/self/fd/0 -> /dev/pts/0
```

Подкаталог _../fd_ обозначает файловый дескриптор. **Файловый дескриптор — это уникальная ссылка на файл или ресурс ввода-вывода (IO)**. Он помогает определить файл или ресурс ввода-вывода, с которым процесс должен работать. Например, каталог _/dev/pts/0_ существует в памяти. Содержимое этого каталога — псевдотерминалы, которые позволяют приложениям получать ввод и отображать вывод:

```text
[root@localhost pts]# ls -l /dev/pts
total 0
crw--w----. 1 root tty  136, 0 Sep 17 12:33 0
c---------. 1 root root   5, 2 Sep 17 09:06 ptmx
```

Кроме того, ещё одна причина наличия символических ссылок в каталоге _/dev_ — переименование. Некоторые приложения могут всё ещё ссылаться на старые имена файлов, отсюда и использование символических ссылок:

```text
[root@localhost dev]# ls -l
total 0
lrwxrwxrwx. 1 root root           3 Sep 17 09:07 cdrom -> sr0
```

## 6. Заключение

В этой статье мы рассмотрели каталог _/dev/_ и его содержимое. Мы разобрались в различных специальных файлах и их функциях. Кроме того, мы обсудили, почему некоторые файлы реализованы как символические ссылки. Подводя итог: каталог _/dev_ — жизненно важная часть *nix-систем. Это связано с тем, что он подчёркивает архитектуру *nix-систем — «всё есть файл».
