# eventfd(2) — man-страница Linux

Источник: [eventfd(2) — Linux manual page](https://man7.org/linux/man-pages/man2/eventfd.2.html)

## ИМЯ

```text
       eventfd - create a file descriptor for event notification
```

eventfd — создать файловый дескриптор для уведомления о событиях

## БИБЛИОТЕКА

```text
       Standard C library (libc, -lc)
```

Стандартная библиотека C (libc, -lc)

## ОБЗОР

```c
       #include <sys/eventfd.h>

       int eventfd(unsigned int initval, int flags);
```

## ОПИСАНИЕ

**eventfd**() создаёт «объект eventfd», который может использоваться как механизм ожидания/уведомления о событиях приложениями пользовательского пространства, а также ядром для уведомления приложений пользовательского пространства о событиях. Объект содержит беззнаковый 64-битный целочисленный счётчик (_uint64_t_), поддерживаемый ядром. Этот счётчик инициализируется значением, указанным в аргументе _initval_.

В качестве возвращаемого значения **eventfd**() возвращает новый файловый дескриптор, который можно использовать для ссылки на объект eventfd.

Следующие значения могут быть объединены побитовым ИЛИ в _flags_ для изменения поведения **eventfd**():

**EFD_CLOEXEC** (начиная с Linux 2.6.27)
Установить флаг close-on-exec (**FD_CLOEXEC**) на новом файловом дескрипторе. Смотрите описание флага **O_CLOEXEC** в [open(2)](../man2/open.2.html), чтобы узнать, чем это может быть полезно.

**EFD_NONBLOCK** (начиная с Linux 2.6.27)
Установить флаг состояния файла **O_NONBLOCK** в описании открытого файла (см. [open(2)](../man2/open.2.html)), на которое ссылается новый файловый дескриптор. Использование этого флага экономит дополнительные вызовы [fcntl(2)](../man2/fcntl.2.html) для достижения того же результата.

**EFD_SEMAPHORE** (начиная с Linux 2.6.30)
Обеспечить семафороподобную семантику для чтений из нового файлового дескриптора. Смотрите ниже.

Вплоть до Linux 2.6.26 аргумент _flags_ не используется и должен указываться равным нулю.

С файловым дескриптором, возвращённым **eventfd**(), можно выполнять следующие операции:

[read(2)](../man2/read.2.html)
Каждое успешное чтение [read(2)](../man2/read.2.html) возвращает 8-байтовое целое число. Вызов [read(2)](../man2/read.2.html) завершается с ошибкой **EINVAL**, если размер предоставленного буфера меньше 8 байт.

Значение, возвращаемое [read(2)](../man2/read.2.html), представлено в порядке байтов хоста — то есть в нативном порядке байтов для целых чисел на хост-машине.

Семантика [read(2)](../man2/read.2.html) зависит от того, имеет ли счётчик eventfd в данный момент ненулевое значение и был ли указан флаг **EFD_SEMAPHORE** при создании файлового дескриптора eventfd:

• Если **EFD_SEMAPHORE** не был указан и счётчик eventfd имеет ненулевое значение, то [read(2)](../man2/read.2.html) возвращает 8 байт, содержащих это значение, а значение счётчика сбрасывается в ноль.

• Если **EFD_SEMAPHORE** был указан и счётчик eventfd имеет ненулевое значение, то [read(2)](../man2/read.2.html) возвращает 8 байт, содержащих значение 1, а значение счётчика уменьшается на 1.

• Если счётчик eventfd равен нулю в момент вызова [read(2)](../man2/read.2.html), то вызов либо блокируется, пока счётчик не станет ненулевым (после чего [read(2)](../man2/read.2.html) выполняется, как описано выше), либо завершается с ошибкой **EAGAIN**, если файловый дескриптор был сделан неблокирующим.

[write(2)](../man2/write.2.html)
Вызов [write(2)](../man2/write.2.html) добавляет 8-байтовое целочисленное значение, переданное в его буфере, к счётчику. Максимальное значение, которое может храниться в счётчике, — это наибольшее беззнаковое 64-битное значение минус 1 (то есть 0xfffffffffffffffe). Если сложение привело бы к превышению счётчиком максимума, то [write(2)](../man2/write.2.html) либо блокируется, пока на файловом дескрипторе не будет выполнено чтение [read(2)](../man2/read.2.html), либо завершается с ошибкой **EAGAIN**, если файловый дескриптор был сделан неблокирующим.

Вызов [write(2)](../man2/write.2.html) завершается с ошибкой **EINVAL**, если размер предоставленного буфера меньше 8 байт или если делается попытка записать значение 0xffffffffffffffff.

[poll(2)](../man2/poll.2.html), [select(2)](../man2/select.2.html) (и аналогичные)
Возвращённый файловый дескриптор поддерживает [poll(2)](../man2/poll.2.html) (и аналогично [epoll(7)](../man7/epoll.7.html)) и [select(2)](../man2/select.2.html) следующим образом:

• Файловый дескриптор доступен для чтения (аргумент _readfds_ у [select(2)](../man2/select.2.html); флаг **POLLIN** у [poll(2)](../man2/poll.2.html)), если счётчик имеет значение больше 0.

• Файловый дескриптор доступен для записи (аргумент _writefds_ у [select(2)](../man2/select.2.html); флаг **POLLOUT** у [poll(2)](../man2/poll.2.html)), если возможно записать значение как минимум «1» без блокировки.

• Если было обнаружено переполнение значения счётчика, то [select(2)](../man2/select.2.html) помечает файловый дескриптор как доступный одновременно и для чтения, и для записи, а [poll(2)](../man2/poll.2.html) возвращает событие **POLLERR**. Как отмечено выше, [write(2)](../man2/write.2.html) никогда не может переполнить счётчик. Однако переполнение может произойти, если подсистема KAIO выполнит 2^64 «постановок сигнала» eventfd (теоретически возможно, но практически маловероятно). Если переполнение произошло, то [read(2)](../man2/read.2.html) вернёт это максимальное значение _uint64_t_ (то есть 0xffffffffffffffff).

Файловый дескриптор eventfd также поддерживает другие API мультиплексирования файловых дескрипторов: [pselect(2)](../man2/pselect.2.html) и [ppoll(2)](../man2/ppoll.2.html).

[close(2)](../man2/close.2.html)
Когда файловый дескриптор больше не нужен, его следует закрыть. Когда все файловые дескрипторы, связанные с одним и тем же объектом eventfd, закрыты, ресурсы объекта освобождаются ядром.

Копия файлового дескриптора, созданного **eventfd**(), наследуется потомком, порождённым [fork(2)](../man2/fork.2.html). Дубликат файлового дескриптора связан с тем же объектом eventfd. Файловые дескрипторы, созданные **eventfd**(), сохраняются при [execve(2)](../man2/execve.2.html), если только не установлен флаг close-on-exec.

## ВОЗВРАЩАЕМОЕ ЗНАЧЕНИЕ

При успешном выполнении **eventfd**() возвращает новый файловый дескриптор eventfd. В случае ошибки возвращается -1, а _[errno](../man3/errno.3.html)_ устанавливается для индикации ошибки.

## ОШИБКИ

**EINVAL** В _flags_ указано неподдерживаемое значение.

**EMFILE** Достигнут предел на количество открытых файловых дескрипторов для процесса.

**ENFILE** Достигнут общесистемный предел на общее количество открытых файлов.

**ENODEV** Не удалось смонтировать (внутреннее) устройство анонимных inode.

**ENOMEM** Недостаточно памяти для создания нового файлового дескриптора eventfd.

## ВЕРСИИ

**Различия между библиотекой C и ядром**
Существует два лежащих в основе системных вызова Linux: **eventfd**() и более новый **eventfd2**(). Первый системный вызов не реализует аргумент _flags_. Последний системный вызов реализует описанные выше значения _flags_. Функция-обёртка glibc будет использовать **eventfd2**(), где он доступен.

**Дополнительные возможности glibc**
Библиотека GNU C определяет дополнительный тип и две функции, которые пытаются абстрагировать некоторые детали чтения и записи на файловом дескрипторе eventfd:

```c
           typedef uint64_t eventfd_t;

           int eventfd_read(int fd, eventfd_t *value);
           int eventfd_write(int fd, eventfd_t value);
```

Эти функции выполняют операции чтения и записи на файловом дескрипторе eventfd, возвращая 0, если было передано корректное количество байт, или -1 в противном случае.

## СТАНДАРТЫ

Linux, GNU.

## ИСТОРИЯ

**eventfd**()
Linux 2.6.22, glibc 2.8.

**eventfd2**()
Linux 2.6.27 (см. ВЕРСИИ). Начиная с glibc 2.9 обёртка **eventfd**() будет использовать системный вызов **eventfd2**(), если он поддерживается ядром.

## ЗАМЕЧАНИЯ

Приложения могут использовать файловый дескриптор eventfd вместо канала (см. [pipe(2)](../man2/pipe.2.html)) во всех случаях, когда канал используется просто для сигнализации о событиях. Накладные расходы ядра на файловый дескриптор eventfd значительно ниже, чем на канал, и требуется только один файловый дескриптор (против двух, необходимых для канала).

При использовании в ядре файловый дескриптор eventfd может обеспечить мост из ядра в пользовательское пространство, позволяя, например, таким подсистемам, как KAIO (kernel AIO), сигнализировать файловому дескриптору о завершении некоторой операции.

Ключевой момент в отношении файлового дескриптора eventfd состоит в том, что его можно отслеживать точно так же, как любой другой файловый дескриптор, с помощью [select(2)](../man2/select.2.html), [poll(2)](../man2/poll.2.html) или [epoll(7)](../man7/epoll.7.html). Это означает, что приложение может одновременно отслеживать готовность «традиционных» файлов и готовность других механизмов ядра, поддерживающих интерфейс eventfd. (Без интерфейса **eventfd**() эти механизмы нельзя было бы мультиплексировать через [select(2)](../man2/select.2.html), [poll(2)](../man2/poll.2.html) или [epoll(7)](../man7/epoll.7.html).)

Текущее значение счётчика eventfd можно посмотреть через запись для соответствующего файлового дескриптора в каталоге _/proc/_pid_/fdinfo_ процесса. Подробнее смотрите [proc(5)](../man5/proc.5.html).

## ПРИМЕРЫ

Следующая программа создаёт файловый дескриптор eventfd, а затем выполняет fork для создания процесса-потомка. Пока родитель недолго спит, потомок записывает каждое из целых чисел, переданных в аргументах командной строки программы, в файловый дескриптор eventfd. Когда родитель заканчивает спать, он читает из файлового дескриптора eventfd.

Следующий сеанс оболочки показывает примерный запуск программы:

```text
           $ ./a.out 1 2 4 7 14
           Child writing 1 to efd
           Child writing 2 to efd
           Child writing 4 to efd
           Child writing 7 to efd
           Child writing 14 to efd
           Child completed write loop
           Parent about to read
           Parent read 28 (0x1c) from efd
```

**Исходный код программы**

```c
       #include <err.h>
       #include <inttypes.h>
       #include <stdio.h>
       #include <stdlib.h>
       #include <sys/eventfd.h>
       #include <sys/types.h>
       #include <unistd.h>

       int
       main(int argc, char *argv[])
       {
           int       efd;
           uint64_t  u;
           ssize_t   s;

           if (argc < 2) {
               fprintf(stderr, "Usage: %s <num>...\n", argv[0]);
               exit(EXIT_FAILURE);
           }

           efd = eventfd(0, 0);
           if (efd == -1)
               err(EXIT_FAILURE, "eventfd");

           switch (fork()) {
           case 0:
               for (size_t j = 1; j < argc; j++) {
                   printf("Child writing %s to efd\n", argv[j]);
                   u = strtoull(argv[j], NULL, 0);
                           /* strtoull() allows various bases */
                   s = write(efd, &u, sizeof(uint64_t));
                   if (s != sizeof(uint64_t))
                       err(EXIT_FAILURE, "write");
               }
               printf("Child completed write loop\n");

               exit(EXIT_SUCCESS);

           default:
               sleep(2);

               printf("Parent about to read\n");
               s = read(efd, &u, sizeof(uint64_t));
               if (s != sizeof(uint64_t))
                   err(EXIT_FAILURE, "read");
               printf("Parent read %w64u (%#w64x) from efd\n", u, u);
               exit(EXIT_SUCCESS);

           case -1:
               err(EXIT_FAILURE, "fork");
           }
       }
```
