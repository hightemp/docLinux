# Как настроить файрвол с UFW в Ubuntu

Источник: [How to Set Up a Firewall with UFW on Ubuntu](https://www.digitalocean.com/community/tutorials/how-to-set-up-a-firewall-with-ufw-on-ubuntu)

## Введение

[UFW, или Uncomplicated Firewall](https://help.ubuntu.com/community/UFW) — это интерфейс к [`iptables`](https://www.digitalocean.com/community/tutorials/iptables-essentials-common-firewall-rules-and-commands), созданный, чтобы сделать настройку файрвола проще. Хотя лежащая в основе система `iptables` мощна и гибка, новичкам её трудно освоить и правильно использовать. UFW упрощает этот процесс, что делает его хорошим выбором для пользователей, которым нужно защитить свою сеть без освоения сложных правил файрвола. Это доступный способ реализовать базовую сетевую безопасность в системе Ubuntu.

Этот руководство объясняет, как настроить файрвол с UFW на Ubuntu. Вы узнаете, как настроить политики по умолчанию, разрешать и запрещать определённые соединения по порту или сервису и управлять правилами файрвола. Мы разберём ключевые шаги: разрешение доступа SSH до включения файрвола, проверку статуса ваших правил и сброс конфигурации при необходимости. Руководство также включает лучшие практики безопасности для эффективного долгосрочного управления файрволом.

<$>[info]
**Ключевые выводы:**

- UFW (Uncomplicated Firewall) выступает дружелюбным к пользователю интерфейсом к `iptables`, упрощая настройку файрвола в системах Ubuntu.
- Для безопасной основы политики UFW по умолчанию должны быть настроены так, чтобы запрещать весь входящий трафик и разрешать весь исходящий.
- Обязательно создайте правило, разрешающее [SSH-соединения](https://www.digitalocean.com/community/tutorials/understanding-the-ssh-encryption-and-connection-process), до включения файрвола, чтобы не потерять доступ к своему серверу.
- Активировать файрвол и настроить его запуск при загрузке можно командой `sudo ufw enable`.
- Правила файрвола можно задавать для разрешения или запрета соединений на основе профилей приложений, имён сервисов, номеров портов или конкретных IP-адресов.
- Команда `sudo ufw status verbose` позволяет проверить, активен ли файрвол, и просмотреть список настроенных правил.
- Правила файрвола можно удалять, ссылаясь на их номер или указывая исходное определение правила.
- Принцип наименьших привилегий должен применяться через открытие только тех портов, которые необходимы для корректной работы ваших приложений.
- Включение логов UFW — лучшая практика для наблюдения за сетевым трафиком и выявления потенциальной вредоносной активности.
- Для автоматизированного реагирования на угрозы UFW можно интегрировать с [системой предотвращения вторжений](https://www.geeksforgeeks.org/ethical-hacking/intrusion-prevention-system-ips/) (Intrusion Prevention System), например [Fail2ban](https://www.digitalocean.com/community/tutorials/how-fail2ban-works-to-protect-services-on-a-linux-server), чтобы динамически блокировать атакующих.

## Шаг 1 — Убеждаемся, что IPv6 включён

В свежих версиях Ubuntu IPv6 включён по умолчанию. На практике это значит, что большинство правил файрвола, добавляемых на сервер, будут включать как IPv4-, так и IPv6-версию — последняя помечается `v6` в выводе команды статуса UFW. Чтобы убедиться, что IPv6 включён, проверьте конфигурационный файл UFW в `/etc/default/ufw`. Откройте его в `nano` или вашем любимом консольном редакторе:

```bash
sudo nano /etc/default/ufw
```

Затем убедитесь, что значение `IPV6` установлено в `yes`. Это должно выглядеть так:

```ini
[label /etc/default/ufw excerpt]
IPV6=yes
```

Сохраните и закройте файл. Если вы используете `nano`, нажмите `CTRL+X`, затем `Y` и `ENTER` для подтверждения.

Когда в одном из следующих шагов этого руководства UFW будет включён, он будет настроен записывать правила файрвола и для IPv4, и для IPv6.

## Шаг 2 — Настройка политик по умолчанию

Если вы только начинаете работать с UFW, хороший первый шаг — проверить политики файрвола по умолчанию. Эти правила определяют, как обрабатывать трафик, который явно не совпадает ни с одним другим правилом.

По умолчанию UFW настроен запрещать все входящие соединения и разрешать все исходящие. Это значит, что любой, кто попытается достучаться до вашего сервера, не сможет подключиться, тогда как любое приложение внутри сервера сможет выйти во внешний мир. Затем вы можете создавать конкретные правила `allow` как исключения из этой политики `deny`.

Чтобы вы могли продолжать следовать остальной части этого руководства, сейчас вы настроите политики UFW по умолчанию для входящего и исходящего трафика.

Чтобы установить входящую политику UFW по умолчанию в `deny`, выполните:

```bash
sudo ufw default deny incoming
```

```text
[secondary_label Output]
Default incoming policy changed to 'deny'
(be sure to update your rules accordingly)
```

Чтобы установить исходящую политику UFW по умолчанию в `allow`, выполните:

```bash
sudo ufw default allow outgoing
```

```text
[secondary_label Output]
Default outgoing policy changed to 'allow'
(be sure to update your rules accordingly)
```

Эти команды устанавливают значения по умолчанию: запрещать входящие и разрешать исходящие соединения. Одних этих значений по умолчанию может быть достаточно для персонального компьютера, но серверам, как правило, нужно отвечать на входящие запросы внешних пользователей. Этим мы займёмся далее.

## Шаг 3 — Разрешение SSH-соединений

Если бы вы включили файрвол UFW прямо сейчас, он запретил бы все входящие соединения. Это значит, что вам понадобится создать правила, явно разрешающие легитимные входящие соединения — например, SSH или HTTP, — если вы хотите, чтобы сервер отвечал на такие запросы. Если вы используете облачный сервер, вы, вероятно, захотите разрешить входящие SSH-соединения, чтобы подключаться к серверу и управлять им.

### Разрешение профиля приложения OpenSSH в UFW

При установке большинство приложений, полагающихся на сетевые соединения, регистрируют в UFW профиль приложения (application profile), что позволяет пользователям быстро разрешать или запрещать внешний доступ к сервису. Проверить, какие профили сейчас зарегистрированы в UFW, можно так:

```bash
sudo ufw app list
```

```text
[secondary_label Output]
Available applications:
  OpenSSH
```

Чтобы включить профиль приложения OpenSSH, выполните:

```bash
sudo ufw allow OpenSSH
```

```text
[secondary_label Output]
Rule added
Rule added (v6)
```

Это создаст правила файрвола, разрешающие все соединения на порту `22` — порту, на котором по умолчанию слушает SSH-демон.

### Разрешение SSH по имени сервиса

Другой способ настроить UFW на разрешение входящих SSH-соединений — сослаться на имя сервиса: `ssh`.

```bash
sudo ufw allow ssh
```

```text
[secondary_label Output]
Rule added
Rule added (v6)
```

UFW знает, какие порты и протоколы использует сервис, на основе файла `/etc/services`.

### Разрешение SSH по номеру порта

Кроме того, можно написать эквивалентное правило, указав порт вместо профиля приложения или имени сервиса. Например, эта команда работает так же, как предыдущие примеры:

```bash
sudo ufw allow 22
```

```text
[secondary_label Output]
Rule added
Rule added (v6)
```

Если вы настроили свой SSH-демон на другой порт, вам придётся указать соответствующий порт. Например, если ваш SSH-сервер слушает порт `2222`, разрешить соединения на этом порту можно такой командой:

```bash
sudo ufw allow 2222
```

```text
[secondary_label Output]
Rule added
Rule added (v6)
```

Теперь, когда файрвол настроен разрешать входящие SSH-соединения, его можно включить.

### Ограничение частоты запросов (rate limiting)

Для защиты сервисов вроде SSH от автоматизированных атак перебором (brute-force) UFW включает возможность ограничения частоты. Когда вы применяете лимит частоты к сервису, UFW отслеживает, как часто пытаются подключиться с каждого исходного IP-адреса. Если IP-адрес делает слишком много соединений за короткий период, UFW временно его блокирует. Это более разумный подход, чем простое разрешение или запрещение трафика, поскольку он различает нормальное использование и поведение, которое, вероятно, является вредоносным.

Чтобы включить ограничение частоты для сервиса, используйте команду `limit` вместо `allow`. Самый частый случай — защита SSH.

```bash
sudo ufw limit ssh
```

Эта единственная команда создаёт правило, разрешающее SSH-соединения, но с условием: если IP-адрес попытается инициировать шесть и более соединений в течение 30 секунд, UFW запретит последующие соединения с этого IP. Это простой и эффективный способ добавить дополнительный уровень защиты сервисам, открытым в интернет.

## Шаг 4 — Включение UFW

Теперь ваш файрвол должен быть настроен разрешать SSH-соединения. Чтобы проверить, какие правила добавлены к текущему моменту, даже пока файрвол ещё отключён, можно использовать:

```bash
sudo ufw show added
```

```text
[secondary_label Output]
Added user rules (see 'ufw status' for running firewall):
ufw allow OpenSSH
```

Убедившись, что у вас есть правило, разрешающее входящие SSH-соединения, включите файрвол:

```bash
sudo ufw enable
```

```text
[secondary_label Output]
Command may disrupt existing ssh connections. Proceed with operation (y|n)? y
Firewall is active and enabled on system startup
```

Вы получите предупреждение о том, что команда может нарушить существующие SSH-соединения. Вы уже настроили правило файрвола, разрешающее SSH-соединения, так что можно продолжать. Ответьте на вопрос `y` и нажмите `ENTER`.

Файрвол теперь активен. Выполните `sudo ufw status verbose`, чтобы увидеть установленные правила. Остальная часть этого руководства подробнее разбирает, как использовать UFW — например, разрешать или запрещать разные типы соединений.

## Шаг 5 — Разрешение других соединений

На этом этапе вы должны разрешить все прочие соединения, на которые ваш сервер должен отвечать. Какие соединения стоит разрешить, зависит от ваших конкретных потребностей. Вы уже знаете, как писать правила, разрешающие соединения на основе профиля приложения, имени сервиса или порта — вы уже сделали это для SSH на порту `22`. То же самое можно сделать для:

- HTTP на порту 80 — его используют веб-серверы без шифрования: `sudo ufw allow http` или `sudo ufw allow 80`
- HTTPS на порту 443 — его используют шифрующие веб-серверы: `sudo ufw allow https` или `sudo ufw allow 443`
- Apache с HTTP и HTTPS одновременно: `sudo ufw allow 'Apache Full'`
- Nginx с HTTP и HTTPS одновременно: `sudo ufw allow 'Nginx Full'`

Не забудьте проверить, какие профили приложений доступны на вашем сервере, командой `sudo ufw app list`.

Есть и другие способы разрешить соединения, помимо указания порта или известного имени сервиса. Некоторые из них мы разберём далее.

### Диапазоны портов

В UFW можно указывать диапазоны портов. Некоторые приложения используют несколько портов вместо одного.

Например, чтобы разрешить соединения X11, использующие порты `6000`–`6007`, выполните:

```bash
sudo ufw allow 6000:6007/tcp
sudo ufw allow 6000:6007/udp
```

Указывая диапазоны портов в UFW, вы обязаны указать протокол (`tcp` или `udp`), к которому применяются правила. Ранее мы об этом не упоминали, потому что отсутствие указания протокола автоматически разрешает оба протокола, что в большинстве случаев допустимо.

### Конкретные IP-адреса

Работая с UFW, вы также можете указывать IP-адреса в правилах. Например, если вы хотите разрешить соединения с конкретного IP-адреса — скажем, рабочего или домашнего адреса `203.0.113.4` — нужно использовать параметр `from`, после которого указать разрешаемый IP-адрес:

```bash
sudo ufw allow from 203.0.113.4
```

```text
[secondary_label Output]
Rule added
```

Также можно указать порт, к которому разрешено подключаться этому IP-адресу, добавив `to any port` и номер порта. Например, если вы хотите разрешить `203.0.113.4` подключаться к порту `22` (SSH), используйте команду:

```bash
sudo ufw allow from 203.0.113.4 to any port 22
```

```text
[secondary_label Output]
Rule added
```

### Подсети

Если вы хотите разрешить целую подсеть IP-адресов, можно использовать [нотацию CIDR](https://en.wikipedia.org/wiki/Classless_Inter-Domain_Routing#:~:text=CIDR%20notation%20is%20a%20compact,bits%20in%20the%20network%20mask.) для указания маски сети. Например, чтобы разрешить все IP-адреса в диапазоне от `203.0.113.1` до `203.0.113.254`, можно использовать команду:

```bash
sudo ufw allow from 203.0.113.0/24
```

```text
[secondary_label Output]
Rule added
```

Аналогично можно указать порт назначения, к которому подсети `203.0.113.0/24` разрешено подключаться. Снова возьмём порт `22` (SSH) в качестве примера:

```bash
sudo ufw allow from 203.0.113.0/24 to any port 22
```

```text
[secondary_label Output]
Rule added
```

### Соединения на конкретный сетевой интерфейс

Если вы хотите создать правило файрвола, применяемое только к конкретному сетевому интерфейсу, это можно сделать, указав `allow in on` и имя сетевого интерфейса.

Возможно, перед продолжением вам захочется узнать имена своих сетевых интерфейсов. Для этого используйте команду:

```bash
ip addr
```

```text
[secondary_label Output Excerpt]
2: eth0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc pfifo_fast state
. . .
3: eth1: <BROADCAST,MULTICAST> mtu 1500 qdisc noop state DOWN group default
. . .
```

Выделенный вывод показывает имена сетевых интерфейсов. Обычно они называются примерно `eth0` или `enp3s2`.

Так, если у вашего сервера есть публичный сетевой интерфейс с именем `eth0`, можно разрешить HTTP-трафик (порт `80`) на него такой командой:

```bash
sudo ufw allow in on eth0 to any port 80
```

```text
[secondary_label Output]
Rule added
Rule added (v6)
```

Это позволит вашему серверу принимать HTTP-запросы из публичного интернета.

Или, если вы хотите, чтобы ваш сервер баз данных [MySQL](https://www.digitalocean.com/community/tutorials/how-to-install-mysql-on-ubuntu-20-04) (порт `3306`) принимал соединения на приватном сетевом интерфейсе `eth1`, можно использовать команду:

```bash
sudo ufw allow in on eth1 to any port 3306
```

```text
[secondary_label Output]
Rule added
Rule added (v6)
```

Это позволит другим серверам в вашей приватной сети подключаться к вашей базе MySQL.

## Шаг 6 — Запрещение соединений

Если вы не меняли политику по умолчанию для входящих соединений, UFW настроен запрещать все входящие соединения. В целом это упрощает создание безопасной политики файрвола, требуя от вас создавать правила, явно разрешающие конкретные порты и IP-адреса.

Однако иногда требуется запретить конкретные соединения по исходному IP-адресу или подсети — возможно, потому что вы знаете, что ваш сервер атакуют именно оттуда. Кроме того, если вы измените свою входящую политику по умолчанию на **allow** (что не рекомендуется), вам потребуется создавать правила **deny** для всех сервисов и IP-адресов, которым вы не хотите разрешать подключения.

Для написания правил **deny** можно использовать описанные выше команды, заменив **allow** на **deny**.

Например, чтобы запретить HTTP-соединения, можно использовать команду:

```bash
sudo ufw deny http
```

```text
[secondary_label Output]
Rule added
Rule added (v6)
```

А чтобы запретить все соединения с `203.0.113.4`, можно использовать команду:

```bash
sudo ufw deny from 203.0.113.4
```

```text
[secondary_label Output]
Rule added
```

В некоторых случаях может понадобиться также блокировать исходящие соединения с сервера. Чтобы запретить всем пользователям использовать порт на сервере, например порт `25` для SMTP-трафика, можно использовать `deny out` с номером порта:

```bash
sudo ufw deny out 25
```

```text
[secondary_label Output]
Rule added
Rule added (v6)
```

Это заблокирует весь исходящий SMTP-трафик на сервере.

## Шаг 7 — Удаление правил

Умение удалять правила файрвола не менее важно, чем умение их создавать. Есть два способа указать, какие правила удалять: по номеру правила или по его человекочитаемому наименованию (аналогично тому, как правила указывались при создании).

### Удаление правила UFW по номеру

Чтобы удалить правило UFW по номеру, сначала нужно получить нумерованный список всех ваших правил файрвола. У команды статуса UFW есть опция вывода номеров рядом с каждым правилом:

```bash
sudo ufw status numbered
```

```text
[secondary_label Numbered Output:]
Status: active

     To                         Action      From
     --                         ------      ----
[ 1] 22                         ALLOW IN    15.15.15.0/24
[ 2] 80                         ALLOW IN    Anywhere
```

Если вы решите удалить правило номер **2** — то, которое разрешает соединения на порт 80 (HTTP), — укажите его в команде удаления UFW следующим образом:

```bash
sudo ufw delete 2
```

```text
[secondary_label Output]
Deleting:
 allow 80
Proceed with operation (y|n)? y
Rule deleted
```

Утилита запросит подтверждение, а затем удалит правило 2, разрешающее HTTP-соединения.

<$>[note]
**Важно:** Команда `ufw status numbered` выводит правила IPv4 и IPv6 отдельными списками. Удаление правила по номеру удалит только эту одну запись. Соответствующее правило (`v6`) нужно определить и удалить отдельно. Напротив, удаление правила по имени (например, `sudo ufw delete allow http`) автоматически удаляет правила и IPv4, и IPv6.
<$>

### Удаление правила UFW по имени

Вместо номеров правил можно ссылаться на правило по его человекочитаемому наименованию, которое строится на основе типа правила (обычно `allow` или `deny`) и имени сервиса, номера порта, для которого оно было создано, либо имени профиля приложения, если он использовался. Например, если вы хотите удалить правило `allow` для профиля приложения с именем `Apache Full`, включённого ранее, используйте:

```bash
sudo ufw delete allow "Apache Full"
```

```text
[secondary_label Output]
Rule deleted
Rule deleted (v6)
```

Команда `delete` работает так же для правил, созданных со ссылкой на сервис по имени или порту. Например, если ранее вы установили правило, разрешающее HTTP-соединения, командой `sudo ufw allow http`, удалить его можно так:

```bash
sudo ufw delete allow http
```

```text
[secondary_label Output]
Rule deleted
Rule deleted (v6)
```

Поскольку имена сервисов взаимозаменяемы с номерами портов при задании правил, можно сослаться на то же правило как на `allow 80` вместо `allow http`:

```bash
sudo ufw delete allow 80
```

```text
[secondary_label Output]
Rule deleted
Rule deleted (v6)
```

При удалении правил UFW по имени удаляются правила и IPv4, и IPv6, если они существуют.

## Шаг 8 — Проверка статуса и правил UFW

В любой момент можно проверить статус UFW командой:

```bash
sudo ufw status verbose
```

Если UFW отключён (а по умолчанию это так), вы увидите примерно следующее:

```text
[secondary_label Output]
Status: inactive
```

Если UFW активен (а так и должно быть, если вы выполняли Шаг 3), в выводе будет сказано, что он активен, и перечислены все установленные правила. Например, если файрвол настроен разрешать SSH-соединения (порт `22`) откуда угодно, вывод может выглядеть примерно так:

```text
[secondary_label Output]
Status: active
Logging: on (low)
Default: deny (incoming), allow (outgoing), disabled (routed)
New profiles: skip

To                         Action      From
--                         ------      ----
22/tcp                     ALLOW IN    Anywhere
```

Используйте команду `status`, если хотите проверить, как UFW настроил файрвол.

## Шаг 9 — Отключение или сброс файрвола

Если вы решите не использовать файрвол UFW, деактивировать его можно командой:

```bash
sudo ufw disable
```

```text
[secondary_label Output]
Firewall stopped and disabled on system startup
```

Все созданные вами с помощью UFW правила перестанут действовать. Вы всегда можете выполнить `sudo ufw enable`, чтобы активировать его позже.

Если у вас уже настроены правила UFW, но вы хотите начать с чистого листа, используйте команду `reset`:

```bash
sudo ufw reset
```

```text
[secondary_label Output]
Resetting all rules to installed defaults. This may disrupt existing ssh
connections. Proceed with operation (y|n)? y
Backing up 'user.rules' to '/etc/ufw/user.rules.20210729_170353'
Backing up 'before.rules' to '/etc/ufw/before.rules.20210729_170353'
Backing up 'after.rules' to '/etc/ufw/after.rules.20210729_170353'
Backing up 'user6.rules' to '/etc/ufw/user6.rules.20210729_170353'
Backing up 'before6.rules' to '/etc/ufw/before6.rules.20210729_170353'
Backing up 'after6.rules' to '/etc/ufw/after6.rules.20210729_170353'
```

Это отключит UFW и удалит все ранее определённые правила, что даст вам свежий старт с UFW. Имейте в виду, что политики по умолчанию останутся такими, какими были установлены в последний раз; их может понадобиться сбросить вручную.

## Лучшие практики безопасности для управления файрволом

Настройка файрвола — лишь первый шаг к защите сервера. Однако поддержание этой безопасности требует постоянного внимания и следования устоявшимся лучшим практикам. Файрвол — это не инструмент «настроил и забыл». Правильное управление гарантирует, что он останется эффективной защитой от несанкционированного доступа.

### Применяйте принцип наименьших привилегий

Самая фундаментальная концепция в безопасности файрволов — [**принцип наименьших привилегий**](https://www.cyberark.com/what-is/least-privilege/) (principle of least privilege). Этот принцип предписывает предоставлять только минимально необходимый уровень доступа для работы сервиса и по умолчанию запрещать все остальные соединения.

UFW спроектирован вокруг этой концепции. Его политика по умолчанию для входящего трафика — `deny`, и это правильная отправная точка. Каждое добавляемое вами правило `allow` должно быть осознанным решением открыть конкретный путь для легитимного трафика.

**Практическое применение:**

- **Будьте конкретны:** вместо открытия широкого диапазона портов открывайте ровно те порты, которые требуются вашим приложениям. Для стандартного веб-сервера это `sudo ufw allow http` и `sudo ufw allow https`.
- **Ограничивайте по источнику:** если сервис должен быть доступен только из определённого места, ограничьте правило этим исходным IP-адресом. Например, чтобы разрешить доступ к базе [MySQL](https://www.digitalocean.com/community/tutorials/create-insert-table-mysql) на порту `3306` только с вашего сервера приложений `203.0.113.100`:

  ```bash
  sudo ufw allow from 203.0.113.100 to any port 3306
  ```

### Регулярно проводите аудит правил файрвола

Требования к серверу меняются со временем. Сервисы добавляются, удаляются или перенастраиваются. Правило файрвола, которое было необходимо полгода назад, теперь может быть лишним риском для безопасности. Важно периодически проводить аудит правил файрвола.

**Практические шаги аудита:**

1. **Выведите список правил:** заведите повторяющееся напоминание (например, раз в квартал) для просмотра конфигурации. Используйте статус `numbered`, чтобы получить чёткий упорядоченный список.

    ```bash
    sudo ufw status numbered
    ```

2. **Оцените каждое правило:** для каждого правила в списке задайте себе вопросы:
    - Всё ли ещё работает и используется сервис, связанный с этим портом?
    - Всё ли ещё уместен уровень доступа (например, `Anywhere` против конкретного IP)?
    - Можно ли сделать правило более строгим без потери функциональности?

3. **Удалите ненужные правила:** если правило больше не нужно, удалите его. Например, если вам больше не нужен доступ FTP, который был правилом номер `[5]` в вашем списке:

    ```bash
    sudo ufw delete 5
    ```

### Включите логи UFW и наблюдайте за ними

Логи файрвола дают ценную информацию о трафике, достигающем вашего сервера, включая заблокированные вредоносные попытки. Без наблюдения за этими логами вы упускаете критически важный источник данных разведки безопасности.

Включить логирование можно простой командой:

```bash
sudo ufw logging on
```

По умолчанию логи UFW пишутся в `/var/log/ufw.log`. Запись лога о заблокированном пакете содержит ключевую информацию, которую можно использовать для выявления закономерностей.

| Поле        | Описание                                                    | Пример           |
| ----------- | ----------------------------------------------------------- | ---------------- |
| `UFW BLOCK` | Действие, выполненное UFW.                                  | `UFW BLOCK`      |
| `SRC=`      | **Исходный IP-адрес**, откуда пришёл пакет.                | `203.0.113.10`   |
| `DST=`      | **IP-адрес назначения** (ваш сервер).                       | `your_server_ip` |
| `PROTO=`    | Используемый сетевой протокол.                              | `TCP`            |
| `DPT=`      | **Порт назначения**, к которому пытался достучаться пакет.  | `22`             |

Регулярно проверяйте эти логи на подозрительную активность — например, когда один IP-адрес многократно пытается подключиться ко множеству разных заблокированных портов, что указывает на сканирование портов.

### Интеграция с системой предотвращения вторжений

Хотя UFW отлично подходит для применения статического набора правил, он не реагирует динамически на активные угрозы. Для автоматизированной, оперативной защиты следует интегрировать UFW с [**системой предотвращения вторжений**](https://www.geeksforgeeks.org/ethical-hacking/intrusion-prevention-system-ips/) (Intrusion Prevention System, IPS), например [**Fail2ban**](https://www.digitalocean.com/community/tutorials/how-fail2ban-works-to-protect-services-on-a-linux-server).

Fail2ban наблюдает за лог-файлами в поисках паттернов вредоносного поведения, таких как повторяющиеся неудачные попытки входа, и автоматически создаёт временные правила файрвола, блокирующие IP-адреса нарушителей. При настройке на работу с UFW Fail2ban будет использовать команды UFW для блокировки атакующих, создавая мощную автоматизированную систему защиты. Такая комбинация позволяет UFW обрабатывать базовую политику безопасности, а Fail2ban — реагировать на активные угрозы в реальном времени.

### Уделяйте внимание и IPv4, и IPv6

Распространённая ошибка — настроить правила файрвола для трафика IPv4 и забыть про IPv6. Современные дистрибутивы Ubuntu включают IPv6 по умолчанию, и если у вашего сервера есть IPv6-адрес, он может стать незащищённой поверхностью атаки, если ваши правила файрвола её не учитывают.

По умолчанию UFW настроен применять правила и к IPv4, и к IPv6. Убедиться в этом можно, проверив основной конфигурационный файл:

```bash
sudo grep "IPV6" /etc/default/ufw
```

```text
[secondary_label Output]
IPV6=yes
```

Когда вы добавляете правило вроде `sudo ufw allow http`, UFW создаёт правило для обоих протоколов. Это видно в выводе статуса:

```text
[secondary_label Output]
To                         Action      From
--                         ------      ----
. . .
80/tcp                     ALLOW       Anywhere
. . .
80/tcp (v6)                ALLOW       Anywhere (v6)
```

**Лучшая практика:**

- **Будьте явными:** всегда проверяйте, что ваши правила применяются к обоим протоколам. При аудите набора правил ищите записи `(v6)`, чтобы убедиться в их парности.
- **Отключите, если не используется:** если ваш сервер или сеть не использует IPv6, наиболее безопасный подход — полностью отключить его на уровне ядра. Это исключает его как потенциальный вектор. Если вы хотите отключить его только для UFW, установите `IPV6=no` в `/etc/default/ufw`.

### Ограничьте исходящий трафик

По умолчанию UFW разрешает весь исходящий трафик с вашего сервера. Это permisive-подход: удобный, но не максимально безопасный. Для серверов в высокозащищённых средах более строгая политика — запрещать весь исходящий трафик по умолчанию и разрешать только конкретные соединения, которые ваш сервер должен инициировать.

Такой подход может помешать скомпрометированному серверу связываться с сервером управления атакующих, эксфильтрировать данные или использоваться для атак на другие системы.

**Практическое применение:**
Это продвинутая техника, требующая тщательного планирования, чтобы не сломать критичные сервисы вроде разрешения DNS-имён или обновления пакетов.

1. **Измените исходящую политику по умолчанию:**

    ```bash
    sudo ufw default deny outgoing
    ```

2. **Разрешите необходимые исходящие соединения:** затем вы должны явно разрешить трафик для сервисов, от которых зависит сервер.

    ```bash
    # Allow DNS queries
    sudo ufw allow out 53

    # Allow access to package repositories and web APIs
    sudo ufw allow out to any port 80 proto tcp
    sudo ufw allow out to any port 443 proto tcp

    # Allow NTP for time synchronization
    sudo ufw allow out 123/udp
    ```

Эти правила нужно адаптировать под конкретные потребности приложений вашего сервера.

### Тестируйте правила до и после применения

Применение неверного правила файрвола может вызвать сбой сервиса или заблокировать ваш доступ к серверу. Лучшая практика — тестировать набор правил до ввода в эксплуатацию и проверять его после.

**Практические шаги тестирования:**

- **Используйте стенд (staging):** по возможности тестируйте сложные изменения правил на не-продуктовом сервере, повторяющем вашу продуктивную среду.
- **Выполните пробный прогон:** у UFW есть опция `--dry-run`, которая показывает, какие изменения были бы внесены, не применяя их на самом деле. Это безопасный способ проверить синтаксические ошибки и увидеть, как ваша команда изменит набор правил.

    ```bash
    sudo ufw --dry-run enable
    ```

- **Проверьте внешним сканированием портов:** после применения правил используйте инструмент вроде `nmap` с внешней машины, чтобы подтвердить состояние сервера. Эта проверка удостоверяет, что порты, которые вы хотите держать открытыми, доступны, а порты, которые должны быть закрыты, — нет.

    ```bash
    # This command checks the state of ports 22, 80, and 443 from an external machine
    nmap -p 22,80,443 your_server_ip
    ```

    Вывод должен показывать `open` для разрешённых портов и `closed` или `filtered` для заблокированных, как и ожидается.

## Часто задаваемые вопросы

### 1. Что такое UFW в Ubuntu?

**UFW** — сокращение от **Uncomplicated Firewall** — это инструмент управления файрволом, используемый в Ubuntu по умолчанию. Он задуман как дружелюбный к пользователю интерфейс к более сложной системе фильтрации пакетов `iptables`. UFW даёт простой способ настраивать правила файрвола и управлять ими без необходимости изучать запутанный синтаксис `iptables`. Его главная цель — сделать ключевые задачи файрвола простыми для пользователей любого уровня подготовки.

### 2. Как включить UFW в Ubuntu?

Включить UFW можно одной командой. Однако прежде чем включать его, вы обязаны сначала создать правило, разрешающее SSH-соединения. Если вы не разрешите SSH-трафик, **при включении файрвола вы потеряете доступ к серверу**.

1. Сначала разрешите SSH-трафик:

    ```bash
    sudo ufw allow ssh
    ```

2. Затем включите файрвол:

    ```bash
    sudo ufw enable
    ```

    Система запросит подтверждение, поскольку включение файрвола может нарушить существующие соединения. Введите `y` и нажмите `ENTER`.

### 3. Как проверить, что UFW работает?

Чтобы проверить текущий статус UFW и увидеть список его правил, используйте команду `status`:

```bash
sudo ufw status
```

Если файрвол активен, вывод покажет `Status: active` и список настроенных правил.

```text
[secondary_label Output]
Status: active

To                         Action      From
--                         ------      ----
22/tcp                     ALLOW       Anywhere
80/tcp                     ALLOW       Anywhere
22/tcp (v6)                ALLOW       Anywhere (v6)
80/tcp (v6)                ALLOW       Anywhere (v6)
```

Если он неактивен, вывод будет `Status: inactive`.

### 4. Как разрешить порт через UFW?

Разрешить трафик на конкретный порт можно командой `allow`. Следует указать как номер порта, так и протокол (обычно `tcp` или `udp`).

Например, чтобы разрешить входящий HTTP-трафик на порт `80`:

```bash
sudo ufw allow 80/tcp
```

Кроме того, UFW часто знает стандартные порты распространённых сервисов, поэтому можно использовать имя сервиса:

```bash
sudo ufw allow http
```

### 5. Что произойдёт, если я заблокирую SSH в UFW?

Если вы заблокируете порт SSH (по умолчанию порт `22`) в UFW, **вы немедленно потеряете удалённое подключение к серверу**. Файрвол будет отбрасывать все новые попытки SSH-соединений, фактически запирая вас снаружи.

Для исправления понадобится доступ к серверу альтернативным способом — например, прямое физическое подключение или веб-консоль от вашего облачного провайдера. Оттуда нужно войти в систему и либо отключить файрвол, либо добавить правило, снова разрешающее SSH-трафик.

### 6. Можно ли использовать UFW вместе с fail2ban?

**Да**, UFW и Fail2ban отлично работают вместе и часто используются как комбинированное решение безопасности.

Fail2ban — это приложение, которое наблюдает за логами сервера в поисках признаков автоматизированных атак, таких как повторяющиеся неудачные попытки входа. Обнаружив вредоносный IP-адрес, оно может автоматически создать временное правило UFW `deny`, блокирующее этот IP. Это обеспечивает автоматизированную систему защиты, где UFW выступает файрволом, а Fail2ban — службой предотвращения вторжений.

### 7. Как сбросить правила UFW?

Чтобы полностью сбросить UFW в состояние по умолчанию, используйте команду `reset`. Она отключит файрвол и удалит все существующие правила. Это действие необратимо.

```bash
sudo ufw reset
```

Вам будет предложено подтвердить действие, поскольку оно снесёт всю вашу конфигурацию файрвола.

## Заключение

Вы научились создавать конкретные исключения для необходимых сервисов вроде SSH и теперь можете добавлять правила на основе профилей приложений, номеров портов или исходных IP-адресов, чтобы разрешать легитимный трафик, блокируя всё остальное.

Помните, что управление файрволом — непрерывный процесс. По мере изменения потребностей вашего сервера периодически проводите аудит правил, удаляя ненужные и обеспечивая безопасность конфигурации. Для изучения более продвинутых правил и распространённых конфигураций смотрите следующие руководства:
